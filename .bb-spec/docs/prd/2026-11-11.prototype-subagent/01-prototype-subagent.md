# 原型子代理

"原型"是改界面前给用户确认用的单文件 HTML 页面。"主对话"是用户直接对话的那个 Claude。"子代理"是主对话派出去单独干活的另一个 Claude：它看不到主对话的内容，只拿到派工时给它的那段话，干完交回一份报告。"原型子代理"是这次新增的、专门出原型和做界面对比的子代理。"派工说明"是主对话派子代理时写给它的那段话。"DESIGN.md"是放在用户项目根目录的设计规范文档。"调用方"是调用 `/prototype` 的一方：`/prd`、`/revise`、`/exec`，或者用户直接运行。

## 用户故事

### P0：作为用 bb-spec 做需求的人，我想要出原型的过程不留在主对话里，以便后面写 PRD、出计划、执行时主对话有更多空间

**用例（主路径）**
- 场景：用户在 `/prd` 里提了一个要改订单列表页的需求，主对话调用 `/prototype order-export --file <路径>`。
- 操作：主对话写好派工说明，派出原型子代理。子代理读 DESIGN.md、画出页面、交回报告。主对话在浏览器里打开原型，把报告原样给用户看。用户说"导出按钮挪到右边"。主对话把这句原话发给同一个子代理。子代理改完交回报告。用户说"可以"。
- 预期：主对话全程没有读项目源码、没有写或读原型文件的内容。子代理交回确认内容清单，`/prd` 照清单写约束和验收。

**用例（边界：子代理有事要问用户）**
- 场景：子代理读完源码，有一个下拉组件定不下来样子，想把项目跑起来看。
- 操作：子代理停下，在报告的「待用户确认的问题」里写明哪部分定不下来、要运行的完整命令和出处。主对话问用户。用户同意。主对话把用户的答复发给子代理。
- 预期：子代理拿到答复之后才启动服务；拿到之前没有启动。

**用例（异常：消息发不到原来的子代理）**
- 场景：用户第二天换了一个新会话，接着改昨天没确认的原型。
- 操作：主对话调用 `/prototype`，原型文件已存在，原来的子代理已经联系不上。
- 预期：主对话新派一个原型子代理，派工说明里写明"原型文件已存在，接着改"并附上用户原话。新子代理读已有原型文件和 DESIGN.md 后只改用户提到的地方，已有的其他内容保持原样。

### P0：作为用 bb-spec 做需求的人，我想要界面对比也由子代理做，以便截图和页面内容不进主对话

**用例（主路径）**
- 场景：`/exec` 全部执行完，调用 `/prototype --compare <原型文件路径>`。
- 操作：主对话新派一个原型子代理做对比。子代理需要跑项目，在报告里写明完整命令和出处。主对话问用户，用户同意，主对话转告子代理。
- 预期：子代理跑起来、截图、逐项对比，交回"一致""不一致""没跑起来"三种结果之一。主对话把结果交给 `/exec`。

## 约束

1. 插件里有一个原型子代理，它的定义里模型写 `fable`。
2. `/prototype` 的出原型和对比两种模式，都由主对话派原型子代理去做。改动再小（只换一个按钮文字、一个颜色值）也派。
3. 主对话在 `/prototype` 里只做这几件事：运行路径脚本确定缓存目录和原型文件路径、写派工说明、派子代理、用 `open` 在浏览器里打开原型文件、把子代理的报告给用户看、问用户、把用户的答复发给子代理、把最后的结果交给调用方。主对话不读项目源码，不读、不写、不改原型文件的内容，不写 DESIGN.md。
4. 出原型的派工说明必须写全 6 项，缺一项就先补齐再派：
   - 模式：出原型
   - 主题
   - 原型文件的完整路径
   - 调用方是谁：`/prd`、`/revise`，或用户直接运行
   - 需求结论：要改哪些页面、每处要改成什么、用户已经明确定下的细节，用户的原话照抄
   - DESIGN.md 应在的完整路径；原型文件旁边已有同名的设计规范临时文件（`.DESIGN.draft.md` 或 `.DESIGN.md`）时，再写它的完整路径
5. 对比的派工说明必须写全 3 项：模式（对比）、原型文件的完整路径、截图目录的完整路径。截图目录是 `ui-compare/<日期>.<主题>/`，名字和原型文件一致。
6. 子代理每轮交回的报告只有这 5 部分，没有内容的部分写"无"：
   - 这一轮改了什么
   - 依据：用到了 DESIGN.md 的哪几节、读了哪些源码文件（写文件路径）、底稿来自哪个地址
   - 哪些是假数据和假操作
   - 哪些部分可能不准，以及原因
   - 待用户确认的问题
   报告里不贴 HTML，不贴源码原文，不贴 DESIGN.md 全文。
7. 主对话把子代理的报告原样给用户看，不删、不改写其中「待用户确认的问题」。原型文件第一次生成后用 `open <原型文件路径>` 打开原型；之后每轮提醒用户刷新页面。
8. 下面这些事，子代理遇到时停下、写进报告的「待用户确认的问题」，拿到主对话转来的用户答复之后才做对应的动作：
   - 新建 DESIGN.md、修改 DESIGN.md
   - DESIGN.md 的不达标项按不按建议改
   - 原型用到 DESIGN.md 里没有的样式，加不加进 DESIGN.md
   - 多套风格、多个方案选哪个
   - 要不要把项目跑起来；要运行的完整命令（连同出处）；端口被占用时用不用现有的服务
9. 用户提了修改意见时，主对话用 SendMessage 把用户的原话发给同一个原型子代理。主对话可以在原话后面补充说明，但不改写原话。
10. 发不到原来的子代理时（没有 SendMessage 工具、找不到那个子代理、已经换了会话），主对话新派一个原型子代理：派工说明在约束 4 的 6 项之外，写明"原型文件已存在，接着改"，并附上用户的原话。新子代理先读已有的原型文件和 DESIGN.md（有草稿读草稿），只改用户提到的地方，其他内容保持原样。
11. 用户明确说"可以"之后，主对话告诉子代理"用户已确认"，子代理交回一份确认内容清单：按页面逐页写出布局、每处文案、每种状态下用户看到什么、每个交互操作后发生什么；原型有多套主题时写出各主题的差异。清单只写框里的内容，不写外壳。
12. 调用方照确认内容清单继续：`/prd` 照它写约束和验收，`/revise` 把它当作期望行为；用户直接运行时，主对话告诉用户原型文件路径后结束。
13. 对比每次新派一个原型子代理。子代理交回的结果是这三种之一：一致；不一致（逐条写原型里是什么、实际是什么，附截图路径）；没跑起来（写清卡在哪）。主对话把结果原样交给调用方。
14. 原型子代理只写这几处：原型文件、原型文件旁边同名的两个设计规范临时文件（`.DESIGN.draft.md`、`.DESIGN.md`）、截图目录；用户同意后才写 DESIGN.md。它不改产品代码，不操作 git。用户同意后启动服务、运行命令或安装依赖是唯一的例外；要安装依赖时，先在「待用户确认的问题」里写明会改动哪些文件。
15. 子代理派不出去时（比如账号用不了 `fable` 模型），主对话停下，把报错原文告诉用户，由用户决定怎么办。主对话不自己接手出原型。
16. `/prd`、`/revise`、`/exec` 调用 `/prototype` 的参数形式保持为 `<主题> --file <路径>` 和 `--compare <路径>`。
17. 一次原型的临时文件都以 `<日期>.<主题>` 开头（日期写成 YYYY-MM-DD，主题用小写字母加横线）：原型是 `ui-preview/<日期>.<主题>.html`，对比截图放在 `ui-compare/<日期>.<主题>/` 目录下。`/revise` 出原型时主题前面加 `revise-`，文件是 `ui-preview/<日期>.revise-<主题>.html`。

- [ ] `/prototype` 规程列出出原型派工说明的 6 项，并写明缺一项先补齐再派。（约束 4）

- [ ] `/prototype` 规程写明报告原样给用户看、原型文件第一次生成后用 `open` 打开、之后提醒刷新。（约束 7）
- [ ] 原型子代理的定义逐项列出约束 8 的那些事，并写明拿到用户答复之后才做。（约束 8）
- [ ] `/prototype` 规程写明用 SendMessage 把用户原话发给同一个子代理、不改写原话。（约束 9）

- [ ] `/prd`、`/revise`、`/exec` 规程里调用 `/prototype` 的参数形式和改动前一致。（约束 16）

## 验证路径

1. 在一个有 DESIGN.md 的项目里运行 `/prototype order-export` → 主对话派出原型子代理；主对话的工具调用里没有读项目源码，也没有读写原型文件。
2. 子代理交回报告 → 报告有 5 部分；原型文件生成后浏览器里打开了原型；主对话把报告原样显示出来。
3. 用户说"导出按钮挪到右边" → 主对话用 SendMessage 把这句原话发给同一个子代理；子代理改完再交报告；主对话提醒刷新页面。
4. 用户说"可以" → 子代理交回确认内容清单，清单按页面写了布局、文案、各状态、各交互结果；主对话告诉用户原型文件路径后结束。
5. 新开一个会话，对同一个原型文件再运行 `/prototype order-export` 并提一条意见 → 主对话新派一个子代理，派工说明里有"原型文件已存在，接着改"；改完后原型里其他内容没变。
6. 运行 `/prototype --compare <原型文件路径>` → 主对话新派一个子代理；需要跑项目时先经主对话问用户；最后返回三种结果之一。
