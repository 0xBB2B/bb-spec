# 设计规范展示页

"DESIGN.md"是放在用户项目根目录的设计规范文档，写颜色、字号、间距、组件样式等。"原型"是改界面前给用户确认用的单文件 HTML 页面。"外壳"是所有原型共用的 HTML 外框，左栏切换页面和状态，右上角切换方案和页面主题；"框"是外壳中间显示正式页面的区域。"设计规范展示页"是这次新增的、把 DESIGN.md 的内容画出来的一种页面，下文简称"展示页"。"不达标项"是 DESIGN.md 里不符合写法标准的地方，比如文字和背景的对比度不够、间距不是 4 的倍数。"设计规范草稿"是用户还没同意的 DESIGN.md 完整内容，存在原型文件旁边，文件名是原型文件名的 `.html` 换成 `.DESIGN.draft.md`。"待写入的设计规范"是用户已经同意、但要等 `/prd` 写 PRD 文件时才写进项目的 DESIGN.md 完整内容，同样存在原型文件旁边，文件名是原型文件名的 `.html` 换成 `.DESIGN.md`。

## 用户故事

### P0：作为确认设计规范的人，我想要看画出来的颜色和组件，以便不读 Markdown 也能判断规范对不对

**用例（主路径：新建规范）**
- 场景：项目有界面代码、没有 DESIGN.md，用户运行 `/prototype order-export`。
- 操作：浏览器打开原型，左栏只有「设计规范」一页。用户看到 12 个色块、5 级字号、7 档间距、圆角和阴影的样例、按钮和输入框的 5 种状态、动效演示；把鼠标移到「默认」一列的按钮上，按钮变色。用户说"可以"。
- 预期：对话里没有出现 DESIGN.md 全文。DESIGN.md 写入项目，「设计规范」一页从原型里删掉，接着出要设计的页面。

**用例（边界：有不达标项）**
- 场景：项目现有的次要文字色是 `#94A3B8`，对白底对比度 2.6。
- 操作：用户打开展示页。
- 预期：页首写着有几项不达标并逐条列出。颜色一节下面有一个橙色虚线框：左格标着「现状 · 不达标」，用 `#94A3B8` 画了一行文字，写着"对白底对比度 2.6:1，正文文字要求至少 4.5:1"；右格标着「建议 · 本页按这个画」，用建议的颜色画了同一行文字和它的对比度。页面其余部分都按建议的值画。

**用例（边界：用户不接受某条建议）**
- 场景：接上例，用户说"次要文字色不改"。
- 操作：子代理按意见改展示页。
- 预期：次要文字色的色块和页面上用到它的地方都改回 `#94A3B8`，那个橙色虚线框去掉，页首的不达标项少一条。用户确认后写入的 DESIGN.md 在「无障碍」一节的例外表里记着这一项、实际值和确认日期。

**用例（主路径：修改已有规范）**
- 场景：项目已有 DESIGN.md，这次原型要用一个规范里没有的警告色，同时把主色加深。
- 操作：用户打开展示页。
- 预期：页首写着这次要改几项并逐条列出。主色和警告色的色块上分别带「本次修改」「本次新增」标签。颜色一节下面有两个紫色虚线框：主色那个左格标「改之前」、右格标「改之后」，各画了一个按钮；警告色那个左格写着"规范里原来没有警告色"，右格画了一条警告提示。

**用例（命令行项目）**
- 场景：项目是命令行工具，没有 DESIGN.md。
- 操作：用户打开展示页。
- 预期：展示页是终端样式的一页，依次列出颜色（每种颜色一行：色块、用途名、色值、对背景的对比度、一句用这个颜色写的示例）、符号、表格样例、进度条样例。

## 约束

1. 下面三种情况，出要设计的页面之前先出展示页，用户确认展示页之后才出要设计的页面：
   - 项目没有 DESIGN.md，要新建
   - 项目的 DESIGN.md 缺项或有不达标项，要修改
   - 原型要用 DESIGN.md 里没有的颜色、字号、间距、圆角、阴影或组件样式，要加进 DESIGN.md
2. 展示页放在同一份原型里，是左栏的一页，名字叫「设计规范」。
3. 项目没有 DESIGN.md、也还没有界面代码时，设计 2 到 3 套风格，每套风格是一个方案，每个方案的「设计规范」页画这套风格；用户在右上角切换方案对比。用户选定后删掉其余方案。
4. 图形界面项目的展示页从上到下依次是：标题「设计规范 · <项目名>」、摘要、颜色、字体与字号、间距、「圆角、边框、阴影」、组件、动效。
5. 摘要按情况写：
   - 新建且全部达标：写一句"全部符合写法标准"
   - 新建且有不达标项：写有几项不达标，逐条列出，并写明"哪一项不想改直接说，那一项按现状画并记进例外表"
   - 修改已有规范：写这次要改几项，逐条列出
6. 「颜色」一节：DESIGN.md 里每种颜色画一个色块，色块下写用途名、色值、用在哪。文字色、边框色、成功色、警告色、错误色写出它对所在背景的对比度；主色写出按钮文字对它的对比度。对比度数值按 WCAG 相对亮度公式算出来。项目有多套主题时在原型里声明多套，色块随右上角的主题切换变成对应那一套。
7. 「字体与字号」一节：写出字体；每一级字号一行，写名字、字号、行高、字重，并用这一级的样式写一行示例文字。
8. 「间距」一节：每个间距值一行，写数值，并画一条宽度等于这个值的色条。
9. 「圆角、边框、阴影」一节：每个圆角值、边框、每种阴影各画一个样例方块，写名字、数值、用在哪。
10. 「组件」一节：
    - 画一张状态对照表，列是默认、悬停、按下、禁用、聚焦，每个组件一行，把每种状态的样子静态画出来
    - 「默认」一列的组件是真的，鼠标移上去、按下、用 Tab 键聚焦时会变成对应状态的样子
    - 组件没有某种状态时，那一格写"没有这个状态"
    - 表格、弹窗、提示条另外各画一个完整样例
    - DESIGN.md 里写了"不适用"的组件不画
11. 「动效」一节：每个动效时长画一个方块，写名字、时长和缓动、用在哪；鼠标移到方块上，方块按这个时长动一次。
12. 新建规范时项目现状有不达标项：展示页按建议改好的值画。每个不达标项在它所在的小节下面加一个对比框：
    - 框是 2px 橙色（`#D97706`）虚线，框内第一行写这一项的名字和它属于哪套主题
    - 左格带「现状 · 不达标」标签（底色 `#FDE68A`、文字 `#422006`），用现状的值画一个样例，写现状的值和原因；原因写出实际数值和要求的数值
    - 右格带「建议 · 本页按这个画」标签（底色 `#BBF7D0`、文字 `#052E16`），用建议的值画同一个样例，写建议的值
    - 左右两格的背景用这一项所属主题的卡片背景色，不随右上角的主题切换变化
13. 用户说某个不达标项不改：展示页上这一项改回现状的值，去掉它的对比框，摘要里去掉这一条。用户确认展示页后，写入的 DESIGN.md 在「无障碍」一节的例外表里记下这一项、实际值、确认日期。
14. 修改已有规范时：
    - 改动的项和新增的项，在它原本的位置带「本次修改」或「本次新增」标签（底色 `#C7D2FE`、文字 `#1E1B4B`）
    - 每个改动或新增的项在所在小节下面加一个对比框：2px 紫色（`#6366F1`）虚线；左格带「改之前」标签，右格带「改之后」标签，各用对应的值画同一个样例并写出值
    - 新增的项左格不画样例，写"规范里原来没有<这一项的名字>"
    - 因不达标而修改的项，用约束 12 的橙色对比框
15. 对比框和标签的颜色固定为约束 12、14 写的值，不随项目配色和主题变化。
16. 命令行项目的展示页是终端样式的页面，依次列出：
    - 颜色：DESIGN.md「终端界面」一节的每种颜色一行，写色块、用途名、色值、对终端背景的对比度，再用这个颜色写一句示例
    - 符号：每个符号和它的含义
    - 表格：一个带表头的样例
    - 进度条：一个样例
    有不达标项或修改项时，在这些内容下面逐项列出：一行「现状 · 不达标」或「改之前」，一行「建议」或「改之后」，各带色块、色值、示例和对比度。
17. 展示页不画 DESIGN.md 的「布局与断点」和「无障碍」两节。
18. 对话里不贴 DESIGN.md 或设计规范草稿的全文。用户要看原文时，告诉用户设计规范草稿的完整路径。
19. 展示页出来之前，设计规范草稿先存到原型文件旁边。用户对展示页提意见时，草稿和展示页一起改，两边的值保持一致。
20. 用户对展示页明确说"可以"，就是同意了这份规范：
    - 被 `/prd` 调用时，把草稿改名成待写入的设计规范（`.DESIGN.draft.md` 改成 `.DESIGN.md`），留在原型文件旁边，由 `/prd` 落盘 PRD 时写入项目
    - 被 `/revise` 调用或用户直接运行时，把草稿写成项目的 DESIGN.md，删掉草稿
21. 用户确认展示页后，「设计规范」一页从原型里删掉，然后出要设计的页面。
22. 用户说这次不想建 DESIGN.md：删掉「设计规范」一页，按草稿出这一次的原型，不写入项目；这次的原型确认后删掉草稿。
23. 原型文件旁边有 `.DESIGN.draft.md`，说明这份规范用户还没同意：接着出展示页请用户确认，不把它当作已同意的规范。原型文件旁边有 `.DESIGN.md`，说明用户已经同意：后面出原型以它为准，不重新起草，不重复报已经确认过的问题。
24. `/prd` 落盘 PRD 时只把 `.DESIGN.md` 写入项目，`.DESIGN.draft.md` 不写入。`/prd` 换到新的工作目录、给 PRD 目录改名、用户选"不做了"时，这两个临时文件跟着原型文件一起搬、一起改名、一起删。

## 验证路径

1. 在一个有界面代码、没有 DESIGN.md、现状有对比度不够的颜色的项目里运行 `/prototype order-export` → 原型左栏只有「设计规范」一页；页首写着不达标项的条数；对话里没有 DESIGN.md 全文。
2. 看颜色一节 → 每种颜色有色块、用途名、色值；不达标的颜色下面有橙色虚线对比框，左格是现状和原因，右格是建议。
3. 看组件一节 → 状态对照表有默认、悬停、按下、禁用、聚焦 5 列；把鼠标移到「默认」一列的按钮上，按钮变成和「悬停」一列一样的样子。
4. 说"第 1 项不改" → 刷新后这一项按现状的值画，它的对比框没了，页首条数少 1。
5. 说"可以" → 项目根目录出现 DESIGN.md，「无障碍」一节例外表里有第 1 项；原型里「设计规范」一页没了，左栏换成要设计的页面。
6. 再运行一次 `/prototype`，这次要用一个规范里没有的颜色 → 先出「设计规范」页，这个颜色的色块带「本次新增」标签，下面有紫色虚线对比框，左格写"规范里原来没有"它。
7. 在一个命令行项目里运行 `/prototype` → 「设计规范」页是终端样式，列着颜色、符号、表格、进度条。
