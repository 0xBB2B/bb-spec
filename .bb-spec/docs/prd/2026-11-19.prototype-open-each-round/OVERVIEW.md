# 每一轮改完原型后打开一次最新版本

## 背景与问题

出原型时，用户每提一次修改意见，AI 就改出一个新版本。原来的规程规定：同一个原型文件，主对话在一次对话里只用 `open` 命令在浏览器里打开一次，之后每一轮只提醒用户"刷新已经打开的页面"。

用户的反馈是：每次改完新版本浏览器都不会弹出来，得自己去找到旧页面、手动刷新才能看到最新版本，很不方便。

再早一版的规则要解决的是"一次出原型弹出 3 个标签页"：当时改一处就打开一次，AI 自己连着修了两处，浏览器里就多了几个标签页。所以新规则仍然要做到：AI 在同一轮里自己改好几遍，也只打开一次。

## 目标

- 每一轮原型改完、需要用户看页面时，浏览器自动弹出最新版本，用户不用手动刷新
- 同一轮里最多打开 1 次

## 非目标

- 不处理旧版本的标签页：每打开一次，浏览器多一个标签页，用户已接受
- 不查找、不复用已经开着的原型标签页
- 只支持 macOS：Windows、Linux 上不做展示原型（`open` 命令只在 macOS 上有）
- 不让原型页面自己检测文件变化并自动刷新
- 不改对比（`--compare`）模式的做法
- 不改原型子代理的报告格式，包括「需要用户看页面」一行的填法

## 整体验证路径

1. 读 `/prototype` 规程「出原型」第 5 步 → 打开原型的条件是"这一轮原型文件改过、最后一份报告写'是'"，时机是这一轮交回给用户之前，做法是执行 `open <原型文件路径>`；搜不到"提醒用户刷新"和"只看主对话自己在本次对话里执行过的 `open`"。
2. 按主路径用例逐轮对照规程 → 只有原型文件改过、报告写"是"的轮次打开，每轮最多打开 1 次。

## 决策记录

- **质疑结论**：值得做。用户每改一版都要手动刷新，频率很高；新规则仍然限定每轮最多打开一次，"一轮弹出好几个标签页"不会回来。
- **每轮直接用 `open` 新开标签页**：用户 2026-11-19 选定。`open` 每执行一次，浏览器就新开一个标签页，内容一定是最新版本（实测：同一文件 3 次 `open`，Chrome 出现 3 个标签页）；任何浏览器都适用。
- **被否决：查找已开着的原型标签页、切过去刷新**：曾按用户提议用 AppleScript 在 Chrome、Safari 里找到标签页再刷新，实现并实测可用。后来实测发现，浏览器自动化工具（playwright、chrome-devtools）会另外启动一个 Chrome，AppleScript 连到那个 Chrome 后找不到用户的标签页，只能退回新开，而用户的环境里经常开着这类工具。用户 2026-11-19 决定改用每轮直接 `open`。
- **被否决：每轮新开浏览器窗口**：要针对 Chrome、Safari 分别写命令，其他浏览器做不到；用户 2026-11-19 选了新开标签页。
- **被否决：让页面自己检测文件变化并刷新**：要改所有原型共用的外壳；直接打开的本地 HTML 文件，浏览器一般不允许页面读取自己所在的文件（推测，没有验证）。
- **代价：旧标签页会留下**：每改一版多一个标签页，用户已知悉并接受。
- **"一轮"的界定**：从用户发一条消息，到主对话把结果交还给用户为止。用户提出："AI 在一次对话里对原型进行自己修改不需要反复弹窗"。
- **原型文件这一轮没改过就不打开**：用户选定。例如用户只问了一句"为什么按钮放这里"，原型没有新版本，打开只会多一个内容相同的标签页。被否决的是"报告写'是'就打开"：没有新版本时也会打开。
- **保留原有的不打开情况**：报告写"否"、对比模式、交回确认内容清单的那一轮都不打开；出原型模式下报告漏写「需要用户看页面」时按"是"处理。这些规则的理由和上一版相同，这次不改。
- **不标 BREAKING CHANGE**：`/prd`、`/revise` 调用 `/prototype` 的方式和参数都不变。
