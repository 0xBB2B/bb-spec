# 每一轮改完打开一次

## 用户故事

### P0：作为出原型的用户，我想要每次提完修改意见后，浏览器自动弹出改好的最新版本，以便不用每次自己去刷新

**用例（主路径）**
- 场景：小王在运行 `/prototype 订单列表加导出按钮`。
- 操作：
  1. 第 1 轮：子代理还没画页面，只问"要不要把项目跑起来看"，报告最后一行写"需要用户看页面：否"。
  2. 第 2 轮：小王答"不用跑"。子代理画完订单列表页，报告写"是"。
  3. 第 3 轮：小王说"导出按钮挪到右边"。子代理改完，报告写"是"。
  4. 第 4 轮：小王问"为什么表头是灰色的"。子代理只回答问题，没改原型文件，报告写"是"。
  5. 第 5 轮：小王说"表头换成白色"。子代理改完，报告写"是"；主对话发现报告里说漏改了一处，又给子代理发了一次消息，子代理再改一次，报告写"是"。
- 预期：第 1、4 轮不打开浏览器；第 2、3、5 轮各在交还给小王之前执行一次 `open <原型文件路径>`，新开的标签页都是这一轮改完后的样子。第 5 轮里子代理改了两次，也只打开 1 次。整个过程主对话不提醒小王刷新页面。

**用例（边界：报告漏了这一行）**
- 场景：出原型模式下，子代理这一轮改了原型文件，报告里没有「需要用户看页面」这一行。
- 操作：主对话收到报告，准备交还给用户。
- 预期：按"是"处理，执行一次 `open`。

## 约束

1. "一轮"指从用户发一条消息，到主对话把结果交还给用户为止。
2. 一轮里原型文件被改过、且这一轮最后一份报告的「需要用户看页面」是"是" → 主对话在所有修改做完、交还给用户之前，执行一次 `open <原型文件路径>`，在浏览器里新开一个标签页。
3. 一轮里最多执行一次 `open`：这一轮主对话多次派活或多次给子代理发消息，只在最后交还给用户之前判断一次。
4. 原型文件这一轮没被改过 → 不执行 `open`。是否改过，以主对话亲自核对的文件修改时间为准（这一轮开始前和交还前各看一次），不看报告里写了什么。
5. 最后一份报告写"否" → 不执行 `open`。
6. 出原型模式下最后一份报告缺「需要用户看页面」这一行 → 按"是"处理。
7. 子代理交回确认内容清单的那一轮、对比（`--compare`）模式转问题和答复时 → 不执行 `open`。
8. 主对话不提醒用户手动刷新页面。
9. `/prototype` 规程运行时，执行 `open <原型文件路径>` 和 `stat -f %m <原型文件路径>` 不弹权限确认。

## 验收

- [ ] `/prototype` 规程写明"一轮"是从用户发一条消息到主对话交还结果为止。（约束 1）
- [ ] `/prototype` 规程写明：这一轮原型文件改过、最后一份报告写"是"时，在交还给用户之前执行一次 `open <原型文件路径>`。（约束 2）
- [ ] `/prototype` 规程写明：一轮里最多执行一次 `open`，多次派活或发消息只在交还前判断一次。（约束 3）
- [ ] `/prototype` 规程写明：原型文件这一轮没改过就不打开，靠主对话在这一轮开始前和交还前各看一次文件修改时间来判断，不看报告措辞。（约束 4）
- [ ] `/prototype` 规程写明：报告写"否"时不打开。（约束 5）
- [ ] `/prototype` 规程写明：出原型模式下报告缺这一行时按"是"处理。（约束 6）
- [ ] `/prototype` 规程写明：交回确认内容清单的那一轮和对比模式不打开。（约束 7）
- [ ] `/prototype` 规程里搜不到"提醒用户刷新"、"已经对这个原型文件执行过 `open`"、"换了新的原型子代理也不重新计数"。（约束 8）
- [ ] `/prototype` 规程的 allowed-tools 放行了 `open` 和 `stat -f %m` 两条命令。（约束 9）
