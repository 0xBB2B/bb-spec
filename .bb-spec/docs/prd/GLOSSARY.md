# 术语表

> 全项目术语唯一权威源，仅 /prd 维护。跨语言 / 跨文档以英文锚点对齐；别名只登记实际用过的语言写法。

| 锚点 | 定义 | 别名 |
|---|---|---|
| ui-preview | 改界面前给用户确认用的单文件 HTML 页面，存放在缓存目录、不进 git | 简体「原型」「界面预览」「预览页」 |
| preview-shell | 所有原型共用的 HTML 外框，由左栏、框上方一行、框三块组成，配色固定暗黑；除框里的内容外都不做进产品 | 简体「外壳」「原型外壳」 |
| preview-frame | 外壳中间显示正式页面的区域，只有这里的内容要做进产品 | 简体「框」 |
| page-theme | 被设计页面自己的一套配色，套数按 DESIGN.md「颜色」一节写了几套决定；原型在填写区用 `themes` 声明，右上角可以切换，框里页面跟着变 | 简体「主题」「页面主题」「明亮主题」「暗黑主题」 |
| preview-scheme | 同一份原型里并列给用户对比的几种设计之一，有短名（如「方案 A」）和一句特点 | 简体「方案」 |
| design-doc | 放在用户项目根目录（多仓库工作区放文档仓库根目录）的设计规范文档，写满风格定位、颜色、字体与字号、间距、圆角边框阴影、布局与断点、组件、动效、无障碍、终端界面 10 节；出原型和写界面代码都以它为依据 | 简体「DESIGN.md」「设计规范」 |
| prototype-base | 读源码定不下来、用户同意把项目跑起来后，从真实页面抓下来放进框里的 HTML 和最终生效的样式（去掉脚本和真实数据）；原型只在它上面改要改的部分 | 简体「底稿」 |
| default-page-style | 项目没有自己的设计时，框里使用的统一页面样式；填写了项目样式后完全不生效 | 简体「默认页面样式」 |
| turn | Claude 从开始工作到把控制权交还给用户的一段连续过程 | 简体「回合」 |
| background-script | Claude 用后台方式启动、运行一段时间后会自己结束的命令，如测试、构建、审查 | 简体「后台脚本」 |
| long-running-service | Claude 用后台方式启动、不会自己结束的命令，如 dev server、watch、`tail -f` | 简体「常驻服务」 |
| new-tech | 项目里原来没有的外部东西：第三方库、框架、编程语言、运行时、数据库、中间件、构建或测试工具、容器镜像、CI Action、外部服务接口；语言标准库、依赖文件里直接声明的、升级已在用依赖的版本都不算；不在标准库里的官方扩展库、代码里直接引用的间接依赖算 | 简体「新技术」 |
| new-tech-list | 引入新技术前给用户批准的清单，每项写名称、类别、来源、用途、现有手段为什么不够、替代方案为什么不选、版本策略 | 简体「新技术清单」「新增技术」 |
| plugin-default-stack | bb-spec 插件规则里预先定好的技术选择，如新前端项目用 Vue 3 + Vite + Tailwind + bun、Go 日志用 `log/slog` | 简体「插件默认栈」「默认技术栈」 |
| root-cause | 一个问题最根本的那处代码缺陷：把它改对，这个问题的各种症状就都消失 | 简体「根因」 |
| same-cause-site | 和用户报的那一处出自同一个根因的其他代码位置：调用了出问题的代码或读了出问题的数据、会受同一缺陷影响；或者在别处独立写了同样的错误写法 | 简体「同根因位置」「同类位置」 |
| unrelated-finding | 干活过程中碰到的、和这次要解决的问题不是同一个根因的问题 | 简体「无关发现」 |
| test-gap | 审查指出的"这条行为有实现、但没有测试覆盖"的地方 | 简体「测试缺口」 |
| prototype-agent | 专门出原型和做界面对比的子代理；主对话派它干活，它看不到主对话的内容，每轮交回一份简短报告 | 简体「原型子代理」 |
| dispatch-brief | 主对话派子代理时写给它的那段话，子代理只能从这里知道要做什么 | 简体「派工说明」 |
| design-showcase | 原型里名叫「设计规范」的一页，把 DESIGN.md 的颜色、字号、间距、圆角、组件各状态和动效画出来给用户确认；用户确认后从原型里删掉 | 简体「设计规范展示页」「展示页」 |
| design-draft | 用户还没同意的 DESIGN.md 完整内容，存在原型文件旁边，文件名是原型文件名的 `.html` 换成 `.DESIGN.draft.md` | 简体「设计规范草稿」「草稿」 |
| design-pending | 用户已经同意、但要等 `/prd` 写 PRD 文件时才写进项目的 DESIGN.md 完整内容，存在原型文件旁边，文件名是原型文件名的 `.html` 换成 `.DESIGN.md` | 简体「待写入的设计规范」 |
