# 原型外壳精简与页面主题切换

外壳是所有原型共用的 HTML 外框，上线后不存在。"框"是外壳中间显示正式页面的区域，只有框里的内容要做进产品。"方案"是同一份原型里并列给用户对比的几种设计。"页面主题"是被设计页面自己的几套配色，比如明亮和暗黑。

## 背景与问题

外壳现在由左栏、框上方一行、底部说明区三块组成，右上角的「☀ 明亮」「☾ 暗黑」切换的是外壳自己的配色，框里的页面不跟着变。用户看原型时遇到三个问题：

- 底部说明区占掉窗口下方最多 30% 的高度，框被压矮。用户确认这块内容不需要，直接去掉。
- 外壳明暗切换用处不大，用户只想要一套暗黑外框。
- 项目的设计规范 DESIGN.md 支持深色模式时要求明暗两套颜色都写，但原型没法切换被设计页面的主题，暗黑那一套画不出来、没法确认。

另外，方案切换现在一律是平铺按钮。方案一多，框上方一行就排不下，要换好几行。

## 目标

- 框占满左栏右边除框上方一行外的全部高度。
- 外壳只有一套暗黑配色。
- 被设计页面有几套主题，原型右上角就能切几套，框里页面的配色跟着变。
- 方案或页面主题达到 4 个时，各自收进一个下拉菜单，框上方一行保持一行排完。

## 非目标

- 底部说明区里的三类内容（画面说明、只在原型里成立的内容、还没确认的问题）不挪到外壳别处，改在对话里讲。
- 左栏的页面、状态切换保持平铺按钮，不随数量变成下拉菜单。
- 默认页面样式只有一套。原型声明了多套主题但没写项目样式时，各主题下框里看起来一样。
- 不改外壳默认终端配色、框里的跳转方式、单个方案时的显示方式。
- 不记住用户切过的主题，每次打开都从第一套开始。
- 已经生成在缓存目录里的旧原型文件不迁移，它们自带旧外壳，照旧能看。

## 依赖与交付顺序

01 → 02 → 03。02 用到 01 腾出来的右上角位置；03 描述 01、02 做完后的外壳。

## 整体验证路径

1. 打开一份只有 1 个方案、没有声明主题的原型 → 外壳是石墨深灰底，右上角没有任何切换，框下面没有说明区，框一直延伸到窗口底部。
2. 打开一份有 3 个方案、声明了「☀ 明亮」「☾ 暗黑」两套主题的原型 → 右上角依次是「方案」和 3 个方案按钮、一条竖线、「主题」和两个主题按钮；点「☾ 暗黑」后框里页面换成暗黑配色，外壳、当前方案、页面、状态都不变。
3. 打开一份有 4 个方案、4 套主题的原型 → 右上角是「方案」下拉菜单和「主题」下拉菜单；在菜单里选第 3 个方案、第 2 套主题，框里跟着变。
4. 读 `/prototype` 规程 → 找不到 `note`、`fake`、`openQuestions` 这三个填写项；规程写明说明、假数据、未确认问题都在对话里讲，主题套数按 DESIGN.md 颜色一节决定，对比时示例数据不同不算不一致。

## 决策记录

- **做不做**：值得做。DESIGN.md 已经要求写明暗两套颜色，原型却只能预览一套；底部说明区用户确认不需要。
- **说明区的内容去哪**：用户选"直接移除，暂不需要"。被否决的方向：挪进左栏（左栏会变长）、做成可收起面板（多一个按钮，还是占地方）。代价：做完后对比真实界面时，没法再靠 `fake` 判断哪些差异是假数据，改由下一条规则解决。
- **对比时假数据怎么处理**：用户选"示例数据不同一律不算错"，对比只看布局、文案、各种状态和交互结果。被否决的方向：对比前在对话里列出假数据请用户确认（每次对比多问一轮）。
- **右上角主题按钮切什么**：用户确认改成切框里被设计页面的主题，外壳固定暗黑。外壳固定用上一份需求选定的石墨深灰配色，没有重新选色。
- **什么时候出现主题切换**：用户选"按 DESIGN.md 颜色一节写了几套"，用户另外要求时也加。被否决的方向：每次出原型前都问用户（DESIGN.md 已经写清楚的事不该再问）。
- **默认显示哪套主题**：用户选"列表里的第一套"，每次打开都一样，想先看哪套就把哪套排第一。被否决的方向：只有明暗两套时跟随系统外观（同一份原型在不同电脑上打开看到的不一样）。
- **几个变成下拉菜单**：用户定的规则，方案和主题都是 1 个不显示、2～3 个平铺按钮、4 个及以上下拉菜单。
- **方案的 `note`（方案取舍说明）**：原来只显示在底部说明区，说明区去掉后没有地方用它，从方案的填写项里删掉；方案的取舍在对话里讲。
- **界面预览**：用户确认了一份三种情况的预览：1 个方案无主题、3 个方案明暗两套、4 个方案 4 套主题。因为这次要设计的就是外壳本身，预览的做法是把新外壳放进旧外壳的框里展示。
