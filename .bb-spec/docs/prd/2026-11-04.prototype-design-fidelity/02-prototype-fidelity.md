# 原型照项目整体还原

"原型"是改界面前给用户确认的 HTML 页面，由 `/prototype` 产出。"外壳"是所有原型共用的外框；"框"是外壳中间显示正式页面的区域；"底部说明"是外壳底部写说明的区域，分「这个画面的说明」「只在原型里成立」「还没确认的问题」三栏。"底稿"是从项目真实页面抓下来的 HTML 和最终生效的样式。

## 用户故事

### P0：作为确认原型的用户，我想要框里就是项目真实页面的样子，以便确认的就是上线后的效果

**用例（主路径：能跑起来）**
- 场景：一个 Vue 后台项目，`package.json` 有 `dev` 脚本，依赖已装好，订单列表页不用登录就能打开。用户要在订单列表的工具栏加一个「导出」按钮。
- 操作：运行 `/prototype 订单导出`。
- 预期：项目被跑起来，订单列表页的真实 HTML 和样式被抓进框里，顶栏、侧边菜单、面包屑、筛选区、表格都和真实页面一样；工具栏里多了「导出」按钮，其余没动。底部说明写着底稿来自哪个地址、这次改了哪些地方。出完原型后项目服务被关掉。

**用例（主路径：跑不起来）**
- 场景：同一个项目，但订单列表页要登录才能看。
- 操作：运行 `/prototype 订单导出`。
- 预期：不尝试登录，改为读入口、路由、布局组件、导航、全局样式、组件库和订单列表页代码，在框里画出整个订单列表页（含顶栏、侧边菜单、面包屑），组件照项目里的结构和类名写。底部说明写清没有跑起来的原因（"页面需要登录"），并列出照着哪些源码文件还原。

**用例（边界：依赖没装）**
- 场景：项目有 `dev` 脚本，但 `node_modules` 不存在。
- 操作：运行 `/prototype`。
- 预期：先问用户要不要安装依赖；用户同意 → 装好后跑起来抓底稿；不同意 → 改为读代码还原，底部说明写明原因。

### P0：作为命令行工具的维护者，我想要终端原型和真实输出一样，以便确认的就是用户在终端里看到的

**用例（主路径）**
- 场景：一个用 Go 写的命令行工具，输出时成功信息用青色、表格用 `│` 分隔。
- 操作：运行 `/prototype 导出命令`。
- 预期：能直接运行命令时，用真实输出当底稿；不能运行时照输出代码和 DESIGN.md「终端界面」一节还原。框里终端的颜色、符号、表格格式和项目实际输出一致，不是外壳的默认四色。

## 约束

**能不能跑起来**
- C1：项目有现成的启动命令（如 `package.json` 的脚本、`Makefile` 目标、README 写明的启动步骤），不用登录、不用另配环境变量、数据库或外部服务，2 分钟内能打开要改的页面 → 判定为"能跑起来"，先跑起来抓底稿。
- C2：依赖没装 → 先问用户要不要装；用户同意才装。
- C3：判定为跑不起来，或跑的过程失败（启动报错、2 分钟内打不开、页面要登录）→ 改用读代码还原，在「只在原型里成立」里写清卡在哪一步。
- C4：为出原型跑起来的服务，原型出完后关掉。

**能跑起来时**
- C5：框里放真实页面抓下来的 HTML 和最终生效的样式，只改这次要改的部分；不改的部分保持原样。
- C6：「这个画面的说明」写明底稿来自哪个地址，以及这次改了哪些地方。

**跑不起来时**
- C7：出原型前读项目的入口、路由、布局组件、导航、全局样式、组件库和改动所在页面的代码。
- C8：框里画出改动所在的整个页面，包括顶栏、侧边栏、导航、页面标题和周围的组件，不只画改动的那一块。
- C9：组件照项目里现有组件的 HTML 结构和类名写。
- C10：「这个画面的说明」列出照着哪些源码文件还原（文件路径）。

**终端原型**
- C11：命令行项目能直接运行要改的命令时 → 用真实输出当底稿；不能运行时 → 照项目的输出代码和 DESIGN.md「终端界面」一节还原颜色、符号、表格和进度条。
- C12：原型可以给终端页面指定项目自己的配色；指定了 → 框里的终端用项目配色；没指定 → 用外壳默认终端配色。
- C13：外壳默认终端配色只在项目没有命令行输出代码时使用。

## 验收

- [ ] C1：`/prototype` 规程写明"能跑起来"的 4 个条件（现成启动命令、不用登录、不用另配环境变量数据库外部服务、2 分钟内打开），满足时先跑起来抓底稿。
- [ ] C2：规程写明依赖没装时先问用户。
- [ ] C3：规程写明跑不起来或失败时改用读代码还原，并在「只在原型里成立」写清卡在哪一步。
- [ ] C4：规程写明原型出完后关掉为出原型跑起来的服务。
- [ ] C5：规程写明框里放真实页面的 HTML 和最终样式，只改要改的部分。
- [ ] C6：规程写明说明里写底稿地址和改动点。
- [ ] C7：规程列出读代码还原前要读的 7 类代码。
- [ ] C8：规程写明框里画整个页面，包括顶栏、侧边栏、导航、页面标题和周围组件。
- [ ] C9：规程写明组件照项目的 HTML 结构和类名写。
- [ ] C10：规程写明说明里列出还原依据的源码文件路径。
- [ ] C11：规程写明终端原型能运行就用真实输出、不能运行就照输出代码和 DESIGN.md 还原。
- [ ] C12：外壳里一个终端页面指定了项目配色时，框里终端的底色和文字颜色是项目配色；没指定时是外壳默认终端配色。指定配色不影响同一份原型里的其他页面。
- [ ] C13：规程写明外壳默认终端配色只在项目没有命令行输出代码时使用。

## 验证路径

1. 在一个能用 `dev` 脚本直接打开页面的项目里运行 `/prototype` → 框里是真实页面加改动，说明里有底稿地址；结束后服务已关闭。
2. 把要改的页面改成需要登录后再运行 → 框里是读代码画出的整个页面，说明里有原因和源码文件清单。
3. 删掉 `node_modules` 后运行 → 先被问要不要装依赖。
4. 在一个命令行项目里出终端原型，并给终端页面指定项目配色 → 框里终端用项目配色；去掉指定 → 变回外壳默认配色。
