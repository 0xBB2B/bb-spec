# 原型统一样式和 /prototype

## 背景与问题

外壳和终端的颜色是固定的，但框里页面的样式每次由 AI 重写，三处配色互不相关。用户每看一份原型都要重新适应，同一种按钮、表格在不同原型里长得不一样。

原型的做法规则还分散在 `/prd`、`/revise` 和用户的个人配置三处，每改一次都要同步三份，容易写漏。这次要加样式规则，又会多一份。

底部说明固定占窗口高度的一定比例。窗口大时内容只有几行，下面全是没有意义的空行，还占掉了框的空间。

## 目标

- 用户看到的所有原型，外壳、默认页面、终端都是同一套样式和配色。
- 项目有自己的设计时，框里还原项目的样子，外壳和页面互不影响。
- 原型的做法只写在一个地方，改一次就全部生效。
- 用户不走完整需求流程，也能单独做原型。

## 非目标

- 不提供主题切换，所有原型只有蓝图这一套外壳样式。
- 不加手机、平板、桌面的宽度切换，框的宽度跟着窗口走。
- 不改"什么时候要出原型"的规则，改动再小也照常要出。
- 不改原型文件的存放位置，也不改 `/prd`、`/revise` 的文件命名。
- `/prototype` 单独运行时不写 PRD，也不改产品代码。

## 依赖与交付顺序

01 → 02。`/prototype` 要写明外壳的填写方式，所以外壳先定。

## 整体验证路径

1. 运行 `/prototype` 做一份不带项目样式的原型 → 外壳是蓝图样式，框里是默认页面样式。
2. 同一份原型填上项目样式 → 框里变成项目的样子，外壳不变。
3. 切换页面和状态 → 框的高度不变，底部没有多余空行。
4. 用 `/prd`、`/revise` 走到界面预览 → 都由 `/prototype` 出原型；用 `/exec`、`/revise` 走到界面对比 → 都按 `/prototype` 的规则对比。

## 决策记录

- **做不做**：值得做。样式不统一的根源是页面样式每次重写，规则分散的根源是同一套规则写了三份，这两处都能一次解决。
- **默认页面底色**：用户确认的预览是浅灰底配白色标题栏和卡片，PRD 最初误写成「白底」，已改成和预览一致；没有改代码，因为用户确认的是预览的样子。
- **选蓝图样式**：我先做了 5 个模板（石墨琥珀、纸白靛蓝、午夜青绿、奶油森绿、黑白朱红），用户先选了石墨琥珀，看到一份蓝图风格的原型后觉得更直观，改选蓝图。蓝图样式里，虚线标注的地方都不属于页面，这比靠配色区分更直接。
- **框里的页面用不用固定配色**：项目没有自己的设计时用默认样式，有的话照实还原。如果一律用默认样式，做完后拿实际界面对比时，有自己设计的项目每次都会对不上。
- **默认样式和项目样式二选一**：写了项目样式，默认样式就完全不生效。两者叠加时，默认样式会混进项目的页面，原型就不是项目真实的样子了。
- **外壳和页面隔离**：用户明确要求内部的原型样式和外部互不影响。预览里用了一个写了全局强制规则的紫色页面验证过，外壳没有变化。
- **底部高度**：放下这份原型里最长的说明，同一份原型里高度固定。用户要求去掉无意义的空行。让底部跟着每个画面变高变矮能完全没有空行，但切换时框的高度会跳，不方便对比，已否决；用户确认了这个取舍。
- **方案标签**：只写方案名，放在框上方右边、「页面 · 状态」的前面，按用户给的参考图。参考图切换框下面写着"最后选哪个，在确认原型窗口里定"，这里不写，因为方案是在对话里选的。
- **skill 名字**：用户定为 `/prototype`。
- **个人全局配置**：用户的 `~/.claude/CLAUDE.md` 也有一节原型规则，改成只留"什么时候要出原型"和"用 `/prototype`"。这个文件不在仓库里，在实施收尾时单独改，不进 PR。
