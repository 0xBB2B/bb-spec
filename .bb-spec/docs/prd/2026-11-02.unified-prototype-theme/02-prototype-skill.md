# /prototype

下文的"外壳"指随插件发布的统一原型外框；"框"指外壳中间显示正式页面的区域。

## 用户故事

### P0：作为维护规则的人，我想要原型规则只写一处，以便改一次就全部生效

**用例（主路径）**
- 场景：要调整多方案的处理方式。
- 操作：只改 `/prototype` 的规则。
- 预期：`/prd`、`/revise` 下次出原型时都按新规则做，不用改这两份规则。

### P0：作为用户，我想要单独做原型，以便先看样子再决定做不做

**用例（主路径）**
- 场景：用户想先看一个页面的几种做法，还没想好要不要立项。
- 操作：运行 `/prototype 订单列表改版`。
- 预期：AI 按规则出一份原型并在浏览器打开，用户说"可以"后结束，告诉用户文件路径；没有写 PRD，没有改产品代码。

### P0：作为用插件做需求的用户，我想要 `/prd`、`/revise` 的原型体验和原来一样，以便流程不被打乱

**用例（主路径）**
- 场景：用户用 `/prd` 提了一个改界面的需求。
- 操作：`/prd` 走到界面预览。
- 预期：`/prd` 调用 `/prototype` 出原型，文件名和 PRD 目录名一致；用户确认后回到 `/prd` 继续。

### P0：作为验收实现的用户，我想要界面对比的规则只有一份，以便各处对比的标准相同

**用例（主路径）**
- 场景：`/exec` 收尾时拿实际界面和原型对比。
- 操作：`/exec` 调用 `/prototype` 的对比模式。
- 预期：只比框里的内容，返回一致、不一致或没跑起来；后续怎么处理由 `/exec` 决定。

## 约束

**skill 本身**
- C1：插件提供 `/prototype` → 用户可以直接运行，`/prd`、`/revise`、`/exec` 也可以调用。
- C2：`/prototype` 的规则写明：什么算界面（图形界面、终端界面）、复制外壳、只改填写区、三类内容各放哪里、各种状态、终端写法、多方案、打开文件、改到用户说"可以"。
- C3：`/prototype` 写明页面样式的判断：项目有自己的设计时，读项目现有样式后写进 `css`，照实还原；没有时 `css` 留空，用默认页面样式。
- C4：`/prototype` 单独运行时 → 不写 PRD、不改产品代码，用户确认后告诉用户文件路径并结束。
- C5：单独运行时，文件存到缓存目录的 `ui-preview/<YYYY-MM-DD>.<主题>.html`；不是 bb-spec 项目时存到会话临时目录。
- C6：`/prd`、`/revise` 调用时可以指定原型文件路径 → 用指定路径；没指定时按 C5。

**调用方**
- C7：`/prd` 的界面预览只写"什么时候出原型"和"调用 `/prototype`，文件名和 PRD 目录名一致"，做法细节都不写。
- C8：`/revise` 的界面预览只写"什么时候出原型"和"调用 `/prototype`，文件名是 `revise-<YYYY-MM-DD>-<主题>.html`"，做法细节都不写。
- C9：`/prd`、`/revise` 把确认过的原型写进约束或作为期望行为时 → 只取框里的内容，外壳不写成产品功能。

**界面对比**
- C10：`/prototype` 提供对比模式 → 把实际界面跑起来，和原型框里的内容逐项对比布局、文案、每种状态、每个交互操作后的结果。
- C11：对比时，外壳不参与对比；「只在原型里成立」写明的假数据和假操作，与实际界面不同不算不一致。
- C12：对比模式返回三种结果：一致、不一致（逐条写原型里是什么、实际是什么）、没跑起来（写清卡在哪）；截图放缓存目录的 `ui-compare/`。
- C13：`/exec`、`/revise` 的界面对比调用 `/prototype` 的对比模式，只写拿到结果后怎么处理，比较的做法都不写。

## 验收

- [ ] C1：`/prototype` 出现在插件的 skill 列表里，能直接运行，也能被调用。
- [ ] C2：`/prototype` 的规则含这些内容：界面两类、复制外壳、填写区、三类内容的位置、各种状态、`terminal: true`、`schemes`、`open`、用户说"可以"。
- [ ] C3：`/prototype` 的规则写明有设计时写 `css` 还原、没有时 `css` 留空。
- [ ] C4：`/prototype` 的规则写明单独运行时不写 PRD、不改产品代码，确认后告诉用户文件路径。
- [ ] C5：`/prototype` 的规则写明单独运行时的文件位置，以及不是 bb-spec 项目时的位置。
- [ ] C6：`/prototype` 的规则写明调用方可以指定文件路径。
- [ ] C7：`/prd` 含 `prototype` 调用，并且不含 `PROTOTYPE-START`、`terminal: true`、`把没选中的方案删掉` 这些做法细节。
- [ ] C8：`/revise` 含 `prototype` 调用和文件名规则，并且不含上面这些做法细节。
- [ ] C9：`/prd` 含「外壳不写成产品功能」，`/revise` 含「外壳不算」。
- [ ] C10：`/prototype` 的规则含对比模式和四项对比内容。
- [ ] C11：`/prototype` 的规则含「不参与对比」「假数据和假操作」。
- [ ] C12：`/prototype` 的规则写明三种结果和截图位置。
- [ ] C13：`/exec`、`/revise` 含 `prototype` 对比调用，并且不含「不参与对比」这句做法细节。

## 验证路径

1. 读 `/prototype` 的规则 → 做法、样式判断、对比规则都在这一处。
2. 读 `/prd`、`/revise`、`/exec` → 都调用 `/prototype`，没有重复写做法。
3. 运行 `tests/validate.sh` → 全部通过，`/prototype` 的结构和引用的外壳文件都被检查到。
