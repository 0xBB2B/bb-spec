# 批准弹窗选项

## 用户故事
### P0：作为批准新技术清单的用户，我想只点"同意"或直接写意见，以便不用按固定格式写编号

**用例（主路径：同意）**
- 场景：`/plan` 列出 Vue 3、PostgreSQL 两项新技术。
- 操作：用户选"同意"。
- 预期：Claude 按清单引入，写进 plan 的「新增技术」表。

**用例（不同意）**
- 场景：同上。
- 操作：用户选"不同意"，Claude 追问后用户回复"第 2 项换成 MongoDB"。
- 预期：Claude 在正文问"要改哪几项？改成什么？"并停下等回复；收到回复后只把第 2 项换成 MongoDB（来源标"用户点名"），第 1 项不变，整份清单再列一遍、再弹一次窗。

**用例（其他）**
- 场景：同上。
- 操作：用户在"其他"里写"第 2 项换成 MongoDB"。
- 预期：Claude 不追问，直接按这句话替换第 2 项，整份清单再列一遍、再弹一次窗。

## 约束
- 批准弹窗的问题仍是"上面 N 项新技术，你同意引入吗？"；预设选项依次是"同意"（选项说明"按这份清单引入"）和"不同意"（选项说明"Claude 接着问你要改哪几项、改成什么"）；工具自带的"其他"用来直接写意见。弹窗里不出现"全部同意，继续""否决其中几项"。
- 用户选"同意"：按清单引入。
- 用户选"不同意"：Claude 在回复正文问"要改哪几项？改成什么？"，停下等用户回复，不再弹窗。
- 用户在"其他"里写意见、或回复了追问：只替换用户提到的项，其余项内容不变；用户说了具体技术的，替换上的项来源标"用户点名"；然后整份清单再列一遍、再弹一次窗，直到用户选"同意"。
- 用户表示不要任何新技术时：改用标准库和项目已在用的技术完成；做不到就停下，说明卡在哪一项需求。
- 这套选项在所有批准新技术的场合都一样：做计划、执行中碰到清单外的新技术、修 bug、普通对话。

## 验收
- [ ] 批准弹窗的问题文字不变，预设选项是"同意""不同意"及各自的说明，不出现"全部同意，继续""否决其中几项"。
- [ ] 选"同意"后按清单引入。
- [ ] 选"不同意"后 Claude 在正文追问"要改哪几项？改成什么？"并停下，不弹窗。
- [ ] 在"其他"里写意见或回复追问后，只替换提到的项、来源标对，整份清单重列并重新弹窗。
- [ ] 用户不要任何新技术时改用现有手段，做不到就停下说明。
- [ ] 做计划、执行、修 bug、普通对话四种场合用的是同一套选项。

## 验证路径
1. 走 `/plan` 到批准弹窗 → 问题和两个预设选项与约束一致。
2. 选"不同意" → 正文出现追问，没有新弹窗；回复后只有被提到的项变化，重新弹窗。
3. 在"其他"里直接写意见 → 不追问，直接替换并重新弹窗。
4. 选"同意" → 开始引入。
