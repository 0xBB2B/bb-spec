# 技术选型弹窗只留同意和不同意

## 背景与问题
引入新技术前，Claude 会把清单逐项列在正文，再弹一次窗请用户批准。现在弹窗的选项是"全部同意，继续"和"否决其中几项"。选"否决其中几项"后，用户还得自己写编号和原因；按钮上什么都写不了，等于多了一步。用户希望技术选型时只需要点"同意"，或者在"其他"里直接写意见。

Claude 的提问工具要求每个问题至少有 2 个预设选项（"其他"由工具自动提供，不算在内），所以不能只留一个"同意"。

## 目标
- 批准弹窗的预设选项只有"同意"和"不同意"，用户也可以在"其他"里直接写意见。
- 用户选"不同意"时，Claude 接着问要改什么，不用用户自己猜要写什么。

## 非目标
- 不改清单的内容和格式（七项内容、来源、理由要求都不变）。
- 不改弹窗的问题文字"上面 N 项新技术，你同意引入吗？"。
- 不改"只替换被改动的项、整份清单再列一遍再弹窗"的处理方式。

## 依赖与交付顺序
单一子需求，无依赖。

## 整体验证路径
1. 让 Claude 走 `/plan`，计划里有 2 项新技术 → 弹窗问题是"上面 2 项新技术，你同意引入吗？"，预设选项依次是"同意""不同意"。
2. 选"不同意" → Claude 在正文问"要改哪几项？改成什么？"，等你回复；回复"第 2 项换成 MongoDB"后，只有第 2 项被替换，整份清单再列一遍、再弹一次窗。
3. 在"其他"里直接写"第 2 项换成 MongoDB" → Claude 不追问，直接替换第 2 项并重新弹窗。
4. 选"同意" → 按清单引入。

## 决策记录
- **第二个预设选项用"不同意"**：用户在 2026-11-04 提出"技术选型的时候回答只需同意和其他自由输入即可"。提问工具要求至少 2 个预设选项，用户在"同意 / 不同意"和"不弹窗、直接打字回复"之间选了前者。否决了"不弹窗"，因为那样用户每次都必须打字才能继续。
- **不同意后在正文追问，不再弹窗**：用户确认过原型。追问的内容是开放的（改哪几项、改成什么），弹窗按钮装不下，直接打字最快。
- **质疑结论**：用户亲自用过一次批准流程后提出，改动小、只影响选项文字和后续处理，值得做。
