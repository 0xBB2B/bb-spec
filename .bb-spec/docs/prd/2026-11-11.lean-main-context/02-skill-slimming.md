# 三个大 skill 瘦身

## 用户故事
### P1：作为用 bb-spec 做需求的用户，我想要调用 skill 时只注入每次都用得上的内容，以便同一个 skill 调用多次时主窗口不被重复的大段文字占满

**用例（主路径）**
- 场景：用户在一个会话里先后做了 3 个小改动，每个都跑一次 `/git-push`，本机没有装 ocr。
- 操作：每次调用 `/git-push`。
- 预期：每次进入主窗口的 `git-push` 正文不超过 12,000 字节。ocr 审查那部分内容没有被读入，推送、开 PR、合并、清理照常完成。

**用例（走到拆出去的那一步）**
- 场景：本机装了 ocr，用户跑 `/git-push`。
- 操作：流程走到 ocr 审查这一步。
- 预期：主窗口先读 ocr 审查对应的那个文件，再按里面的规则跑审查、核实、定级，结果和拆分前一样。

**用例（落盘 PRD）**
- 场景：用户用 `/prd` 对齐完一个需求，流程走到落盘。
- 操作：主窗口准备写 `OVERVIEW.md` 和子需求文档。
- 预期：主窗口先读文档模板所在的文件，写出来的 PRD 结构和拆分前一样。

## 约束
1. `git-push`、`revise` 两个 skill 的 `SKILL.md` 文件大小各不超过 12,000 字节；`prd` 的 `SKILL.md` 不超过 18,000 字节。
2. 拆出去的内容放在该 skill 自己目录下的文件里，每个文件只装某一步才用到的内容（如文档模板、ocr 审查、合并后清理、多仓库处理）。
3. 正文在用到的那一步写明"走到这一步先读 <文件>"，写的路径指向的文件必须存在。
4. 每次调用都要用到的内容留在正文：核心原则、步骤顺序、每一步做什么的概要、禁止操作。`prd` 每次都要走的步骤（读取配置、现状扫描、意图定性、质疑、澄清、收敛、方案质检）全文留在正文，只搬落盘时才用的内容（文档模板、落盘细则、多仓库布局）。
5. 拆分只搬位置，不改规则：拆分前 `SKILL.md` 里的每条规则，拆分后在正文或它目录下的文件里能找到，文字不变。
6. 仓库里现有的规则测试在拆分后全部通过；测试原来在 `SKILL.md` 里找的规则文字搬走了的，改成在搬去的文件里找。
7. 插件校验脚本通过。

## 验收
- [ ] 对应约束 1：`git-push`、`revise` 的 `SKILL.md` 字节数各不超过 12,000，`prd` 的不超过 18,000。
- [ ] 对应约束 2：三个 skill 目录下有拆出去的文件，每个文件开头写明它在哪一步用。
- [ ] 对应约束 3：正文里每一处"先读 <文件>"指向的文件都存在；每个拆出去的文件都在正文里被指到至少一次。
- [ ] 对应约束 4：三个正文里仍有核心原则、完整的步骤顺序和禁止操作；`prd` 目录下拆出去的文件不超过 4 个。
- [ ] 对应约束 5、6：`tests/` 下全部测试文件通过。
- [ ] 对应约束 7：`tests/validate.sh` 通过。

## 验证路径
1. 在本分支执行 `wc -c` 看三个 `SKILL.md` → `git-push`、`revise` 各不超过 12,000，`prd` 不超过 18,000。
2. 跑 `tests/` 下全部测试 → 全部通过。
3. 用本分支的插件在装了 ocr 的机器上跑一次 `/git-push` → 会话记录里能看到主窗口在 ocr 这一步读了对应文件，审查结果按原来的格式输出。
4. 用本分支的插件跑一次 `/prd` 到落盘 → 会话记录里能看到主窗口读了模板文件，生成的 `OVERVIEW.md` 含背景、目标、非目标、子需求清单、整体验证路径、决策记录。
