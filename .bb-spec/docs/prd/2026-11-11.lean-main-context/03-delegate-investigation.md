# 调查交给子代理

## 用户故事
### P0：作为用 bb-spec 做需求的用户，我想要主窗口把翻源码找答案的活交给子代理，以便主窗口只留下结论

**用例（主路径：不知道答案在哪）**
- 场景：用户用 `/revise` 报"保存草稿后版本号没变"，主窗口不知道版本号在哪几个文件里计算。
- 操作：主窗口开始诊断。
- 预期：主窗口派调查子代理，说明要查的问题和已知线索。子代理交回不超过 2,000 字符的报告：每条结论带 `文件:行号`。主窗口没有自己搜索、翻读这些源码文件。

**用例（已知位置）**
- 场景：用户说"`src/order/export.ts` 里的超时是多少"。
- 操作：主窗口要回答这个问题。
- 预期：主窗口直接读这个文件里相关的那一段，不派子代理。

**用例（关键结论核对）**
- 场景：调查子代理报告"根因在 `src/draft/save.ts:88`，保存后没有更新版本号"。主窗口准备按这个根因改代码。
- 操作：主窗口动手之前。
- 预期：主窗口读 `src/draft/save.ts` 第 88 行附近的那一段，确认和报告一致后才开始修。

**用例（核对不一致）**
- 场景：主窗口按行号读到的代码和调查报告说的不一样。
- 操作：主窗口发现不一致。
- 预期：主窗口以自己读到的代码为准，不采用这条结论，重新调查这一点。

**用例（没查到）**
- 场景：调查子代理找不到用户说的那个功能的代码。
- 操作：子代理交回报告。
- 预期：报告写明"没查到"，并列出查过哪些目录、用过哪些关键词。不猜测。

## 约束
1. 插件新增一个调查子代理：只读代码和文档，不改任何文件，不操作 git，使用 sonnet 模型。
2. 调查子代理的报告不超过 2,000 字符：每条结论一行并带 `文件:行号`；没查到的写"没查到"加查过的范围；超出的细节写进缓存目录下 `reports/` 里的一个文件，报告里用一行给出它的完整路径。
3. 在 `/prd`、`/revise`、`/exec` 里，主窗口要弄清"系统现在怎么做"或"问题出在哪"，并且不知道答案在哪个文件、或预计要读 3 个以上源码文件 → 派调查子代理，主窗口不自己搜索和翻读。
4. 已经知道文件和大概位置 → 主窗口自己读那一段（定点读），不派子代理。
5. 下面三类读取留在主窗口：读 PRD、plan、AGENTS.md 等文档；看 `git diff` 验收子代理的改动；定点读。
6. 调查子代理交回的、带 `文件:行号` 的结论，算作"本次实际读过的代码"，主窗口可以用它回答和讨论。
7. 两类关键结论，主窗口必须先按行号定点读、确认和报告一致，才能使用：要写进 PRD 的现状；要据此改代码的根因。
8. 定点读到的代码和报告不一致 → 以主窗口读到的为准，这条结论作废，重新调查这一点。
9. 插件模板里 AGENTS.md「查功能、查问题的规矩」第 1 条，写明结论可以来自主窗口本次读过的代码，也可以来自调查子代理本次交回的带 `文件:行号` 的结论；仍然要求还没依据时说"还没确认"。
10. 派工时主窗口给调查子代理的内容包括：要回答的问题、已知线索（功能名、相关 PRD 目录、报错文字）、项目根路径。
11. 插件说明（`plugin.json`、`marketplace.json`）和 README 里的子代理清单写上调查子代理，数量和实际一致。

## 验收
- [ ] 对应约束 1：调查子代理的定义文件存在，模型为 sonnet，写明只读、不改文件、不操作 git。
- [ ] 对应约束 2：定义文件里有 2,000 字符上限、每条结论带 `文件:行号`、没查到时的写法、细节文件放在缓存目录 `reports/` 下并在报告里给完整路径。
- [ ] 对应约束 3、4：`/prd`、`/revise`、`/exec` 的规则里都写明派调查子代理的两个条件和定点读的条件。
- [ ] 对应约束 5：三个 skill 的规则里写明三类留在主窗口的读取。
- [ ] 对应约束 6、7、8：三个 skill 的规则里写明结论可以直接用于回答和讨论、两类关键结论先定点核对、不一致时以读到的代码为准并重查。
- [ ] 对应约束 9：`/prd` 的 AGENTS.md 模板第 1 条含调查子代理结论这个来源；本仓库的 AGENTS.md 同一条文字和模板一致。
- [ ] 对应约束 10：三个 skill 的规则里写明派工内容的三项。
- [ ] 对应约束 11：两份插件说明和 README 里出现调查子代理，写的子代理数量和 `agents/` 目录下的文件数一致。

## 验证路径
1. 用本分支的插件在一个不熟悉的项目里跑 `/revise`，报一个不知道代码在哪的问题 → 会话记录里主窗口派了调查子代理，交回报告不超过 2,000 字符，每条结论带 `文件:行号`。
2. 同一份记录里看主窗口动手修之前 → 有一次按报告行号的定点读。
3. 同一份记录里数主窗口读源码和搜索的命令 → 只剩定点读，没有连续翻读 3 个以上源码文件的搜索过程。
4. 再问一个指明了文件的问题 → 主窗口直接读那一段，没有派子代理。
