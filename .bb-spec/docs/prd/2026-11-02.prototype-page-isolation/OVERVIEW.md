# 原型里分清正式页面和设计说明

## 背景与问题

`/prd` 和 `/revise` 在改界面前会先出一个 HTML 原型，请用户确认后才动手。现在的规则只要求还原布局、画出各种状态，没有规定说明文字和切换按钮放在哪，每次由 AI 自己决定。

用户看原型时，说明、切换按钮和正式页面混在同一个页面里，分不清哪些要做进产品，哪些只是为了看原型才加的。看不懂就没法放心确认，而确认这一步本来就是为了防止做错。

实现完成后的界面对比也有同样的问题：规则没说哪部分才算正式页面，对比时没有明确的范围。

## 目标

- 用户打开任意一份原型，一眼能分清哪部分要做进产品。
- 所有原型的外观和操作方式都一样，用户不用每次重新适应。
- 原型有多个方案时，用户始终知道当前看的是哪个方案，并能方便地切换对比。

## 非目标

- 不加手机、平板、桌面的宽度切换，框的宽度跟着窗口走。
- 不改"什么时候要出原型"的规则，改动再小也照常要出。
- 不改原型文件的存放位置和命名。
- 不提供把原型自动转成产品代码的能力。

|---|---|---|---|

## 依赖与交付顺序

01 → 02。流程规则要用到 01 做好的外壳。

## 整体验证路径

1. 用外壳做一份有 2 个方案、3 个页面的原型，其中一个页面是终端界面 → 浏览器能直接打开，分成左栏、框、底部说明三块。
2. 切换方案、页面、状态 → 框里只出现正式页面，左栏、框上方提示和底部说明都跟着变。
3. 读 `/prd`、`/revise`、`/exec` 的规则 → 都写明用外壳出原型，界面对比只比框里的内容。

## 决策记录

- **做不做**：值得做。用户看不懂原型时，确认环节就失去了作用。
- **说明放哪**：说明放在框的下方，切换放在左栏。最早的方案把说明和切换都放左栏，用户看预览后要求把页面说明挪到页面下方单独留出的位置。
- **外观**：深色外壳、琥珀色分界线、框上方提示语、底部三列说明，都来自用户给的参考图。
- **怎么保证统一**：选随插件发一个固定外壳，每次只填内容。只加文字规则时外壳每次由 AI 重写，颜色和结构可能不一样，已否决。
- **多方案**：放在同一份原型里切换，切换入口放在左栏最上方并单独描边，框上方一直标出当前方案。这是用户看预览时提出的要求。只有一个方案时全部不显示，免得多占位置。
- **选定方案后**：把没选中的方案从原型里删掉。这样实现完成后对比时只有一个标准，不用再判断该比哪个方案。
- **终端界面**：内容从左上角开始、底色铺满框，和真实终端全屏时一样。预览里曾居中显示，用户看后要求改掉。
- **个人全局配置**：用户的 `~/.claude/CLAUDE.md` 也有一节原型规则，用户要求一起改。这个文件不在仓库里，在实施收尾时单独改，不进 PR。
