# 原型外壳的明暗主题和方案切换

外壳是所有原型共用的 HTML 外框，由左栏、框上方提示、底部说明组成。"框"是外壳中间显示正式页面的区域，只有框里的内容要做进产品。"方案"是同一份原型里并列给用户对比的几种设计。

## 背景与问题

外壳现在是藏蓝底（`#12264a`）配亮青色（`#7fd4ff`）虚线。用户看原型时觉得晃眼，盯久了不舒服。实际算出来的对比度（数字越大，两种颜色的亮度差越大）：

- 框里的白色页面对外壳底色是 15.0:1。正式页面多半是浅色，眼睛要在一大块白和一圈深蓝之间来回适应。
- 青色线条对底色是 9.1:1，而且左栏分界、框外圈、底部分界、方案框都是这种亮青色虚线，选中的按钮还整块填成亮青色。

另外，方案切换和页面、状态切换都挤在左栏里。用户对比方案时要在一长串按钮里找方案，分不清哪组按钮切的是方案、哪组切的是当前方案里的页面。

## 目标

- 外壳的线条和选中按钮不刺眼，线条对底色的对比度在 4.5 到 5.5 之间。
- 浅色系统下看网页原型时，外壳和白色页面的亮度差小；深色系统下外壳是深色。
- 方案切换和页面、状态切换分开放，一眼能看出在切哪一种。

## 非目标

- 不改终端原型的配色。终端照真实终端的样子画，两种主题下都是深色底。
- 不改默认页面样式和项目样式，框里的页面在两种主题下完全一样。
- 不记住手动切换的主题，每份原型打开时都跟系统一致。
- 只有明亮、暗黑两套主题，不提供第三套，也不让用户自定义颜色。
- 不改底部说明的高度规则、框里的跳转方式、原型填写区的格式。

## 依赖与交付顺序

01 → 02。两个子需求都改框上方一行的右侧，主题切换固定在最右端，方案按钮排在它左边，所以先定主题切换。

## 整体验证路径

1. 系统设成浅色，打开一份有 2 个方案的原型 → 外壳是雾灰蓝底；框上方右侧依次是方案按钮和「☀ 明亮 / ☾ 暗黑」；左栏只有页面和状态两组切换。
2. 点右上角「☾ 暗黑」→ 外壳变成石墨深灰，框里的页面和当前方案、页面、状态都不变。
3. 点右上角另一个方案 → 框里换成这个方案，左栏选中的页面和状态不变。
4. 关掉原型，把系统改成深色，再打开 → 外壳是暗黑主题。

## 决策记录

- **做不做**：值得做。原型每个界面需求都要看好几轮，刺眼的问题每次都会碰到。
- **怎么选的配色**：先在同一份原型里做了 7 套外壳配色对比（浅色蓝图、深色调暗、暖纸墨蓝、石墨深灰、鼠尾草绿、极简白灰、雾灰蓝），布局全一样，只换颜色。用户选了雾灰蓝做明亮主题、石墨深灰做暗黑主题。
- **为什么要两套主题**：上一份 PRD（2026-11-02.unified-prototype-theme）的非目标写了"不提供主题切换"，这次推翻。原因是单一外壳顾不了两头：深色外壳对白色网页的对比度是 14.8 到 15.8，浅色外壳对深色终端的对比度是 12.7 到 17.1，总有一种页面亮度差大。跟系统一致后，用户在什么环境下看，外壳就是什么深浅。
- **雾灰蓝为什么不选更浅的**：雾灰蓝对白色页面是 1.4:1，比浅色蓝图（1.1）、极简白灰（1.0）高一点，框在哪一眼能看出来；它对深色终端是 12.7:1，是浅色方案里最小的。
- **选中按钮的样式**：现在是整块填亮青色，这是刺眼的来源之一。改成强调色细线框加一层和底色接近的浅填充。
- **不记住手动切换**：用户确认。记住要把设置存进浏览器，而原型是双击打开的本地文件，不同浏览器对本地文件能不能存设置表现不一样，没有验证过，存不住时用户会以为功能坏了。
- **系统切换深浅时跟着变**：用户确认。只在用户还没手动切过时跟着变，手动切过就以用户的选择为准，免得刚切完又被系统改回去。
- **终端配色不动**：用户确认。终端原型画的是真实终端的样子，属于正式页面，不属于外壳。
- **方案切换的位置**：用户要求放到整个页面的右上方，左栏只切当前方案的页面和状态。左栏顶部写当前方案名，免得切页面时忘了在看哪个方案。
- **方案很多时怎么排**：方案按钮一行放不下就换行，左边的提示文字始终完整显示。考虑过收进下拉菜单，但那样要多点一下才能看到有哪些方案，原型里已演示换行的样子，用户确认。
- **长标题怎么排**：ocr 审查发现「页面名 · 状态名」约 40 字以上会把页面撑出横向滚动条。用户看过修订原型后确认（2026-11-04）：标题自动折行，提示文字保持一行，右侧按钮整组换到下一行。否掉了截断加省略号，因为标题要始终完整显示。
- **框高度在切页面时可以变**：标题长短不同会让框上方一行变高变矮，框高度跟着变；实测 960 宽、2 个方案时差 5 像素，7 个方案时右侧按钮可能多一行。用户确认（2026-11-04）切换方案时框高度不变即可，切换页面、状态时允许变。否掉了按最长标题给标题区固定宽度，因为要多维护一套测量逻辑和真实浏览器测试，换来的只是几像素到一行按钮高的稳定。
