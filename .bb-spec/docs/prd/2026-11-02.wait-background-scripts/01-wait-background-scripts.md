# 等待后台脚本

## 用户故事
### P0：作为使用 bb-spec-core 的用户，我想要 Claude 等后台脚本跑完再结束回合，以便收到“回合完成”时任务真的完成了

**用例（主路径）**
- 场景：用户让 Claude 跑全部测试，Claude 用后台方式启动 `npm test`，然后准备结束回合。
- 操作：`npm test` 需要 4 分钟，用户不做其他操作。
- 预期：屏幕出现一次 Stop hook feedback 提示，列出 `npm test`。Claude 用前台循环等待，每次最多 2 分钟，脚本结束后才汇报结果并结束回合。

**用例（常驻服务）**
- 场景：用户让 Claude 启动 dev server，Claude 用后台方式启动 `npm run dev`。
- 操作：Claude 准备结束回合，之后用户继续发消息。
- 预期：出现一次提示，Claude 判断这是常驻服务，直接结束回合，服务继续运行。之后的回合都不再提示这条命令。

**用例（脚本和服务同时存在）**
- 场景：Claude 同时启动了 `npm test` 和 `npm run dev`。
- 操作：Claude 准备结束回合。
- 预期：提示里列出两条命令。Claude 只等 `npm test`，跑完后结束回合，`npm run dev` 继续运行。

**用例（等待时用户发消息）**
- 场景：Claude 正在前台等待脚本。
- 操作：用户发来一条消息。
- 预期：这次前台等待结束后 Claude 处理这条消息，最长约 2 分钟。

## 约束
1. 回合结束时，后台任务里有类型为 `shell`、状态为 `running`、本会话没提示过的命令 → 输出一次提示，让 Claude 继续工作。屏幕显示 “Stop hook feedback”，不显示 “Stop hook error”。
2. 提示内容按下面的格式，每条命令一行，只列本次新发现的命令：
   ```
   后台命令还在运行：
   - <任务编号>: <命令>
   会自己结束的脚本（测试、构建、审查）：用前台 Bash 循环等它结束，每次最多等 2 分钟，没结束就再等一次，看完结果再结束回合。
   常驻服务（dev server、watch、tail -f）：不用等。全部是常驻服务时，直接结束回合。
   ```
3. 同一会话里，已经提示过的任务编号再次出现 → 不提示，放行。
4. 列表里既有提示过的也有新的命令 → 只列新的，并把新的也记为已提示。
5. 同一个任务编号在另一个会话里出现 → 按没提示过处理。
6. 后台任务列表为空、字段缺失、只有 `subagent` / `monitor` 等非 `shell` 类型、或状态不是 `running` → 不输出，放行。
7. 命令超过 80 个字符 → 只显示前 80 个字符并加 `…`。命令里的换行显示成空格。
8. 没有 `jq`、输入不是合法 JSON、缺少会话编号、会话编号带路径分隔符或 `..` → 不输出，放行，退出码为 0。
9. 已提示记录写不进去 → 不输出，放行，退出码为 0，避免同一条命令每个回合都被提示。
10. 已提示记录不写进用户的项目目录。
11. 子代理结束时不触发这个提示。
12. `/git-push` 启动 ocr 审查后，用前台循环等待它结束，每次前台调用最多等 2 分钟，不靠结束回合等完成通知。
13. `plugin.json`、`marketplace.json` 对 bb-spec-core 的说明和 README 的钩子表都写上这个新钩子，钩子数量和实际一致。

## 验收
- [ ] 对应约束 1：输入一条新的运行中 shell 任务 → 输出 `hookSpecificOutput.additionalContext`，`hookEventName` 为 `Stop`，没有 `decision` 字段，退出码为 0。真实交互会话里屏幕显示 “Stop hook feedback”。
- [ ] 对应约束 2：输出文本和约束里的格式逐字一致，两条新命令时有两行 `- ` 列表。
- [ ] 对应约束 3：同一会话、同一编号连续调用两次 → 第二次无输出。
- [ ] 对应约束 4：先提示 A，再输入 A 和 B → 输出只含 B；再输入 A 和 B → 无输出。
- [ ] 对应约束 5：会话 1 提示过 A，会话 2 输入 A → 有输出。
- [ ] 对应约束 6：空列表、缺字段、`subagent`、`monitor`、`completed` 各输入一次 → 都无输出、退出码为 0。
- [ ] 对应约束 7：81 个字符的命令显示前 80 个字符加 `…`；80 个字符的命令完整显示；含换行的命令显示在一行内。
- [ ] 对应约束 8：去掉 `jq`、非法 JSON、缺会话编号、会话编号为 `../x` 和 `a/b` → 都无输出、退出码为 0，且没有文件写到记录目录之外。
- [ ] 对应约束 9：记录位置不可写 → 无输出、退出码为 0。
- [ ] 对应约束 10：运行后项目目录没有新增文件。
- [ ] 对应约束 11：`hooks.json` 在 `Stop` 下注册这个钩子，`SubagentStop` 下没有。
- [ ] 对应约束 12：`git-push` 的 ocr 步骤写明前台循环等待和 2 分钟上限，没有“等完成通知”的写法。
- [ ] 对应约束 13：三处说明都提到新钩子，`tests/validate.sh` 通过。
- [ ] 主路径：真实交互会话里，约 45 秒的后台脚本跑完之前，Claude 不汇报、不结束回合。
- [ ] 常驻服务：真实交互会话里，服务保持运行，Claude 结束回合，下一条消息不再提示。
- [ ] 等待时发消息：真实交互会话里，前台等待期间发的消息在约 2 分钟内得到回复。
- [ ] 真实 Vibe42：用户跑一条超过 1 分钟的后台脚本，脚本跑完之前没有弹出“回合完成”通知。这一项由用户人工确认。

## 验证路径
1. 跑钩子的行为测试 → 全部通过。
2. 跑 `tests/validate.sh` → 通过。
3. 用加载本分支插件的交互式 Claude 跑后台脚本和常驻服务 → 屏幕提示和确认过的预览一致，Claude 等完脚本、放过服务。
4. 用户在真实 Vibe42 里跑一条超过 1 分钟的后台脚本 → 脚本跑完之前没有通知。
