# 等后台脚本跑完再结束回合

## 背景与问题
用户让 Claude 跑测试、构建或审查时，Claude 常常把脚本放到后台，然后马上结束回合，等脚本跑完再被唤醒。这段时间屏幕回到输入框，Vibe42 这类工具会判断 Claude 已经空闲，用户就在任务没完成时收到“回合完成”的通知。

用户本机最近 60 个会话的记录显示：2342 次回合结束里，至少 282 次是在等后台脚本，其中 238 次等了 60 秒以上，等待时间中位数约 12 分钟。

## 目标
- 后台脚本还在跑时，Claude 等它跑完再结束回合。
- 常驻服务不影响 Claude 结束回合，每条服务只多提示一次。
- 钩子出任何问题都放行，不让回合卡住。

## 非目标
- 不处理后台子代理：本次范围只含后台脚本，用户已确认。
- 不修改 Claude Code 或 Vibe42 的判断规则：两者的规则都在各自的程序里。
- 不提供单独的关闭开关：不想要时停用 bb-spec-core 插件。
- 不靠命令文字判断脚本和服务：`npm run dev` 和 `npm run build` 只看文字分不清。

## 整体验证路径
1. 在交互模式下让 Claude 用后台方式启动一条约 45 秒的脚本和一个常驻服务，并要求它立刻结束回合 → 屏幕出现一次 Stop hook feedback 提示，列出两条命令。
2. 继续观察 → Claude 用前台循环等到脚本结束才汇报，服务保持运行。
3. 再发一条普通消息 → Claude 正常回复，没有新的提示。
4. 在真实 Vibe42 里跑一条超过 1 分钟的后台脚本 → 脚本跑完之前没有弹出“回合完成”通知。

## 决策记录
- **用 Stop 钩子强制，不只写规则**：只在 CLAUDE.md 写规则靠模型自觉，不能保证每次遵守。关掉 Vibe42 的通知只是藏起症状，真正完成时也收不到。
- **每条命令一生只提示一次，由 Claude 判断类型**：启动命令的 Claude 最清楚它是脚本还是服务，比按命令文字猜更准。按会话记住问过的编号，服务开着时后续回合不再多花一次模型调用。否决了“每个回合都拦一次”：服务开一整天时，每个回合都多一次调用。
- **用反馈提示，不用拦截决定**：实测 `decision: block` 显示 “Stop hook error”，底部还有报错条；`additionalContext` 显示 “Stop hook feedback”，同样能让 Claude 继续工作。正常流程不该看起来像出错。
- **每次前台等待最多 2 分钟**：等待期间用户发的消息要等这次调用结束才被处理。实测 30 秒上限时消息延迟 25 到 31 秒。按 12 分钟的中位数估算，30 秒上限要约 24 次调用，10 分钟上限会让消息最长等约 10 分钟，2 分钟约 6 次调用，消息最长等约 2 分钟。
- **不算破坏性变更**：没有删除或改名公开接口，使用者不用迁移，只是回合结束得更晚。按普通 feat 发版。
- **不加开关**：用户确认不需要，少一个配置项。
- **已知残留**：实测 5 次拦截里有 2 次出现短暂空闲闪动，精确采样的一次约 0.3 秒。Vibe42 会不会因此发通知要在真实环境验收。
- **质疑结论**：有本机记录作证据，问题真实且频繁，值得做。
