# 原文对照表

## 用户故事
### P0：作为以后维护这个功能的人，我想要在 PRD 里查到原文每一条最后去了哪里、为什么，以便有人拿着原文来问"这条为什么没做"时能直接回答

**用例（主路径）**
- 场景：导入了 `a.md`（S1~S6）和 `b.md`（S7~S8），用户挑中「订单导出」；S5、S6 属于「登录改用验证码」；S3 用户选了按规矩改；S8 删除。
- 操作：步骤 7 落盘。
- 预期：OVERVIEW「决策记录」里有一张原文对照表，S1~S8 每个编号各占一行，写出处、原文要点、去向、原因；S5、S6 去向为"另开 PRD"；S8 写了删除原因；去向为"写成约束"的行写明落在哪份子需求文档的第几条约束。

**用例（边界 / 异常）**
- 场景：对照表漏写了 S4。操作：步骤 8 自检。预期：自检不通过，补上 S4 这一行后重新自检。
- 场景：对照表写 S2 落在 `01-export.md` 约束 3，但那份文件只有 2 条约束。操作：步骤 8 自检。预期：自检不通过，改正对照表或补上约束后重新自检。
- 场景：普通对话方式运行 `/prd`，没带原文。操作：落盘。预期：「决策记录」里没有原文对照表，自检也不查这一项。

## 约束
1. 导入模式落盘时，OVERVIEW「决策记录」里写一张原文对照表，列为：编号、出处、原文要点、去向、原因。
2. 本次读入的所有原文条目，包括没挑中、去向为"另开 PRD"的，每个编号在对照表里各占一行。
3. 去向为"写成约束"的行，写明落在哪份子需求文档的第几条约束；去向为"写进非目标"的行，对应内容出现在 OVERVIEW「非目标」里。
4. 去向为"删除"和"另开 PRD"的行，原因一栏必须填写；其他去向的原因一栏可以不填。
5. 对照表的出处只写文件名和章节，不写原文的完整路径或链接，也不把原文复制进仓库。
6. 导入模式下，步骤 8 自检多查三项：原文每个编号都在对照表里；"写成约束"的行指向的约束确实存在；"删除"和"另开 PRD"的行都有原因。任何一项不满足，自检不通过，改正后重新自检。
7. 普通对话方式运行 `/prd` 时，不写原文对照表，步骤 8 也不查这一项。

## 验收
- [ ] 约束 1：导入模式落盘的 OVERVIEW「决策记录」里有原文对照表，五列齐全。
- [ ] 约束 2：对照表的编号覆盖本次读入的全部原文条目，没挑中的条目也在。
- [ ] 约束 3：每个"写成约束"的行都写了子需求文档和约束序号；每个"写进非目标"的行在「非目标」里能找到对应内容。
- [ ] 约束 4：每个"删除"和"另开 PRD"的行原因都不为空。
- [ ] 约束 5：对照表里没有原文的完整路径或链接；仓库里没有新增原文的副本。
- [ ] 约束 6：故意漏掉一个编号、或写一个不存在的约束序号时，步骤 8 自检不通过。
- [ ] 约束 7：不带原文运行 `/prd` 时，OVERVIEW 里没有原文对照表。

## 验证路径
1. 准备 `a.md`（S1~S6，含「订单导出」「登录改用验证码」两个章节）和 `b.md`（S7~S8），运行 `/prd @a.md @b.md`，挑「订单导出」，走到步骤 7 → OVERVIEW「决策记录」里有对照表，S1~S8 都在，"另开 PRD"和"删除"的行都有原因，"写成约束"的行指向的约束都能在子需求文档里找到。
2. 手动删掉对照表里的一行，让 `/prd` 重新自检 → 自检报告缺这个编号。
3. 不带原文运行一次 `/prd` 并落盘 → OVERVIEW 里没有原文对照表。
