# 做计划时的新技术清单

## 用户故事
### P0：作为用 bb-spec 做项目的用户，我想在做计划时看到所有要引入的新技术和理由，以便在动手前决定用不用

**用例（主路径）**
- 场景：用户在空项目里通过 `/prd` 定好了"图书馆系统"的需求，进入 `/plan`。
- 操作：`/plan` 盘点到要用 Vue 3、Go、PostgreSQL、Redis。用户看完清单，选"全部同意，继续"。
- 预期：Claude 先在正文里逐项列出这 4 项。每项都有名称、类别、来源、用途、现有手段为什么不够、替代方案为什么不选、版本策略。Vue 3 和 Go 的来源标"插件默认栈"，PostgreSQL 标"Claude 提议"。接着只弹一次窗，问"上面 4 项新技术，你同意引入吗？"。用户同意后，plan 文档里出现七栏的「新增技术」表，然后开始执行。

**用例（否决其中一项）**
- 场景：同上，用户这次想用 MongoDB。
- 操作：选"否决其中几项"，写"第 3 项，这次想用 MongoDB"。
- 预期：Claude 只把第 3 项换成 MongoDB，来源标"用户点名"，第 1、2、4 项一字不改。然后把整份清单再列一遍、再弹一次窗。用户选"全部同意，继续"后才开始执行。

**用例（不要任何新技术）**
- 场景：用户在弹窗"其他"里写"不要加新东西"。
- 操作：Claude 改用标准库和项目已有的技术重新设计。
- 预期：能做到时，新方案的清单为空，直接继续。做不到时，Claude 停下，说明哪一项需求离不开新技术、卡在哪里，不自行引入。

**用例（没有新技术）**
- 场景：在已有项目里加一个小功能，只用到标准库和项目已在用的依赖。
- 预期：`/plan` 不列清单、不弹窗，plan 文档里没有「新增技术」表。

## 约束
- 新技术指项目里原来没有的外部东西：第三方库、框架、编程语言、运行时、数据库、中间件、构建或测试工具、容器镜像、CI Action、外部服务接口。语言标准库、项目已在用的东西不算；升级已在用依赖的版本也不算。不在标准库里的官方扩展库（如 Go 的 `golang.org/x/*`）算新技术；项目已在用只认依赖文件里直接声明的，只出现在 lockfile、`go.sum` 或 `// indirect` 里的间接依赖，代码里要直接引用时也算新技术。
- 计划用到的新技术全部列出，来源是插件默认栈、用户点名的也要列，一项都不能省。
- 每项写齐七项内容：名称、类别、来源（插件默认栈 / 用户点名 / Claude 提议三选一）、用途、现有手段为什么不够、替代方案为什么不选、版本策略。用户点名的项也要写"现有手段为什么不够"和"替代方案为什么不选"。
- "现有手段为什么不够"和"替代方案为什么不选"要写具体原因。只写"业界常用""更优雅""更流行"这类对任何选择都成立的话，不算写了理由。
- 清单写在回复正文里，每项分几行写。之后只弹一次窗，问题是"上面 N 项新技术，你同意引入吗？"，N 是清单项数。选项依次是"全部同意，继续"、"否决其中几项"（写要否决的编号和原因），工具自带的"其他"用来写别的意见。
- 用户否决其中几项时，Claude 只替换被否决的项，其余项内容不变；替换上的项按用户意见确定来源（用户说了具体技术就标"用户点名"）。然后把整份清单再列一遍、再弹一次窗，直到用户选"全部同意，继续"。
- 用户不要任何新技术时，Claude 改用标准库和项目已有的技术重新设计；做不到就停下，说明卡在哪一项需求，不自行引入。
- 用户选"全部同意，继续"之前，不写 plan 文档，也不开始执行。
- 用户同意后，清单写进 plan 文档的「新增技术」表，七栏依次是：名称、类别、来源、用途、现有手段为什么不够、替代方案为什么不选、版本策略，内容和用户批准的清单一致。
- 计划没有用到新技术时，不列清单、不弹窗，plan 文档里没有「新增技术」表。

## 验收
- [ ] 清单覆盖约束里列出的所有类别：数据库、容器镜像、CI Action 等也会出现在清单里，标准库和项目已在用的不出现。
- [ ] `golang.org/x/*` 这类官方扩展库、代码里直接引用的间接依赖出现在清单里。
- [ ] 插件默认栈和用户点名的项出现在清单里，来源标对。
- [ ] 每项都有七项内容；用户点名的项也有两条理由。
- [ ] 理由只写"业界常用""更优雅""更流行"时算不合格，`/plan` 自检能查出来。
- [ ] 清单写在正文；整份清单只弹一次窗，问题和选项文字与约束一致。
- [ ] 否决第 3 项后，只有第 3 项变化，整份清单重新列出并重新弹窗。
- [ ] 用户不要任何新技术时，改用现有手段；做不到时停下说明，不引入。
- [ ] 用户同意前没有 plan 文档、没有开始执行。
- [ ] plan 文档的「新增技术」表是七栏，内容和批准的清单一致。
- [ ] 没有新技术时不弹窗、没有「新增技术」表。

## 验证路径
1. 在空项目走 `/prd` 做图书馆系统并通过 → `/plan` 在正文逐项列出新技术，每项七项内容齐全，默认栈标"插件默认栈"。
2. 弹窗里否决数据库那一项，写"想用 MongoDB" → 只有这一项换成 MongoDB 并标"用户点名"，整份清单重新列出并重新弹窗。
3. 选"全部同意，继续" → plan 文档出现七栏「新增技术」表，内容与清单一致，开始执行。
4. 在已有项目里加一个只用标准库的小功能 → `/plan` 不弹窗，plan 文档没有「新增技术」表。
