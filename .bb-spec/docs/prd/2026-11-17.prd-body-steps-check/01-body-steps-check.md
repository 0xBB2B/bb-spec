# 步骤 0 到 5 留在正文的检查

## 用户故事
### P0：作为维护 bb-spec 的人，我想要体量测试直接检查步骤 0 到 5 的内容留在 `prd/SKILL.md` 正文里，而不是限制 references 的文件个数，以便按落盘用途合理拆分文件，同时防住把每次都走的步骤搬出正文

**用例（主路径）**
- 场景：维护者要把一段落盘时才用的规则拆成 `prd/references/` 下的第 5 个文件（1,200 字节），并在正文步骤 7 写上"走到这一步先读"它。
- 操作：跑 `bash tests/skill-size.test.sh`。
- 预期：全部通过；输出里没有"文件数不超过"这一项。

**用例（边界 / 异常）**
- 场景：有人把步骤 2 的内容搬进 references，正文步骤 2 只剩标题和一句"走到这一步先读 `references/challenge.md`"。操作：跑测试。预期：失败，报告步骤 2 一节缺少关键句"有没有更便宜的替代"，并报告步骤 2 一节出现了"走到这一步先读"。
- 场景：有人把步骤 1 的标题改名或删掉。操作：跑测试。预期：失败，报告找不到步骤 1 的标题。
- 场景：步骤 1 的关键句被挪到步骤 3 的小节里。操作：跑测试。预期：失败，报告步骤 1 一节缺少关键句；只要求它出现在正文别处不算通过。
- 场景：步骤 0 里有"走到这一步先读 `references/repo-layout.md`"和导入模式的先读提示（现状）。操作：跑测试。预期：通过，步骤 0 不受先读提示的限制。

## 约束
1. `tests/skill-size.test.sh` 不再限制 `prd/references/` 下的文件个数。
2. 步骤 0 到 5 的标题都必须在 `prd/SKILL.md` 正文里，原文分别是：`### 步骤 0：读取配置 + 现状扫描`、`### 步骤 1：意图定性`、`### 步骤 2：质疑（对用户可见）`、`### 步骤 3：澄清与发散`、`### 步骤 4：收敛与拆解`、`### 步骤 5：方案质检`。缺任何一个，测试失败并写明缺哪个标题。
3. 下面每条关键句必须出现在它所属步骤的小节里（小节 = 从这一步的标题行到下一个同级或更高级标题之前，只看 `SKILL.md`）：步骤 0 `**重叠判定**`；步骤 1 `用一句话复述**要解决的问题**`；步骤 2 `有没有更便宜的替代`；步骤 3 `**怎么呈现选项**`；步骤 4 `钉死**目标**与**非目标**`；步骤 5 `是否可证伪`。不在所属小节里，测试失败并写明哪一步缺哪句。
4. 步骤 1 到 5 的小节里出现"走到这一步先读"时，测试失败并写明是哪一步。步骤 0 不做这项检查。
5. "references 每个文件不小于 600 字节"、正文字节上限、正文指到的 references 路径都存在、每个 references 文件名都在正文里出现，这几项检查保持不变。

## 验收
- [ ] 约束 1：`prd/references/` 下有 5 个都不小于 600 字节、且都被正文提到的文件时，测试通过；测试脚本里没有文件个数上限的检查。
- [ ] 约束 2：删掉或改掉 6 个标题中的任意一个，测试失败并写明缺的标题。
- [ ] 约束 3：6 条关键句都在所属小节里时通过；把任一条挪到别的步骤小节里，测试失败并写明哪一步缺哪句。
- [ ] 约束 4：在步骤 1 到 5 任一小节加一句"走到这一步先读 `references/x.md`"，测试失败并写明是哪一步；步骤 0 现有的两句先读提示不导致失败。
- [ ] 约束 5：其他检查项照常运行，现有 `prd/SKILL.md` 和 references 下测试全部通过。

## 验证路径
1. 跑 `bash tests/skill-size.test.sh` → 全部通过。
2. 临时在 `prd/references/` 加第 5 个 1,200 字节的文件并在正文步骤 7 提到它 → 通过；撤回。
3. 临时把步骤 2 的内容换成一句先读提示 → 失败，报告缺关键句和出现先读提示；撤回。
4. 临时把步骤 1 的关键句挪进步骤 3 → 失败，报告步骤 1 缺关键句；撤回。
5. 再跑一次 → 全部通过。
