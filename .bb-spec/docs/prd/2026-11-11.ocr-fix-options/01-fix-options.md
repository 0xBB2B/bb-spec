# 修哪些的选项

「建议修复」表是 Claude 核实后认为成立的问题，每条定为 🔴、🔶、🔷 三级之一。「不建议修」表是核实后认为不成立或不值得修的问题，条目用字母编号。

## 用户故事
### P0：作为走 `/git-push` 的用户，我想直接点默认选项就把建议修复的问题全修掉，以便不用每次找范围最大的那一项

**用例（主路径：三级都有）**
- 场景：ocr 审查核实后成立 🔴 1 条、🔶 2 条、🔷 1 条，不成立 1 条。
- 操作：用户看到弹窗，选第一项。
- 预期：弹窗选项依次是「全部修复（🔴🔶🔷）」（带推荐标记）、「只修重点（🔴🔶）」、「只修核心（🔴）」、「全不修复」。选第一项后，4 条成立的条目交给 `/revise`，不成立的那 1 条没有交过去。

**用例（边界：没有 🔷）**
- 场景：成立 🔴 1 条、🔶 2 条。
- 操作：用户看到弹窗。
- 预期：选项依次是「全部修复（🔴🔶）」（带推荐标记）、「只修核心（🔴）」、「全不修复」。

**用例（边界：没有 🔴）**
- 场景：成立 🔶 2 条、🔷 1 条。
- 操作：用户看到弹窗。
- 预期：选项依次是「全部修复（🔶🔷）」（带推荐标记）、「只修重点（🔶）」、「全不修复」。

**用例（边界：没有 🔶）**
- 场景：成立 🔴 1 条、🔷 1 条。
- 操作：用户看到弹窗。
- 预期：选项依次是「全部修复（🔴🔷）」（带推荐标记）、「只修核心（🔴）」、「全不修复」。

**用例（边界：只有一级）**
- 场景：只成立 🔷 1 条。
- 操作：用户看到弹窗。
- 预期：选项依次是「全部修复（🔷）」（带推荐标记）、「全不修复」。只成立 🔴 或只成立 🔶 时同理，括号里是那一级的图标。

**用例（拉回不建议修的条目）**
- 场景：成立 🔴 1 条（编号 1），「不建议修」表有 1 条（编号 A）。
- 操作：用户在「其他」里输入 `1,A`。
- 预期：编号 1 和编号 A 两条交给 `/revise`。

## 约束
- 弹窗的问题文字是「ocr 核实后建议修 C 条（🔴 a · 🔶 b · 🔷 c），修哪些？」。
- 选项按这个顺序排：「全部修复」「只修重点」「只修核心」「全不修复」。
- 每个选项修的范围：「全部修复」修「建议修复」表里的全部条目；「只修重点」修其中的 🔴 和 🔶；「只修核心」只修 🔴；「全不修复」一条都不修。四个选项都不包含「不建议修」表里的条目。
- 前三个选项名后面带全角括号，括号里按 🔴🔶🔷 的顺序写这个选项这次实际会修到的等级的图标；这次审查没有出现的等级不写。「全不修复」不带括号。
- 某个选项这次一条都修不到 → 去掉它。
- 「只修重点」和「只修核心」修的范围相同 → 去掉「只修重点」。
- 其余情况下，某个选项和排在它前面的选项修的范围相同 → 去掉它。
- 「全不修复」始终保留。
- 推荐标记标在剩下的第一个选项上，写在等级括号后面，如「全部修复（🔴🔶🔷）(Recommended)」。
- 用户选「其他」时按输入的编号取，如 `1,3,A`，可以包含「不建议修」表的字母编号。
- 用户选「全不修复」→ 不调用 `/revise`，进入全量测试。选其余选项或输入编号 → 选中的条目一次全部交给 `/revise`。
- 弹窗和相关说明里不出现「修全部 🔴🔶」「只修 🔴」「建议项全修」「都不修」这四个选项名。

## 验收
- [ ] 问题文字是「ocr 核实后建议修 C 条（🔴 a · 🔶 b · 🔷 c），修哪些？」。
- [ ] 三级都有时，选项依次是「全部修复（🔴🔶🔷）」「只修重点（🔴🔶）」「只修核心（🔴）」「全不修复」。
- [ ] 选「全部修复」交出去的是「建议修复」表的全部条目；选「只修重点」是 🔴 和 🔶；选「只修核心」是 🔴；三者都不含「不建议修」表的条目。
- [ ] 没有 🔷 时括号里没有 🔷：选项是「全部修复（🔴🔶）」「只修核心（🔴）」「全不修复」。
- [ ] 没有 🔴 时没有「只修核心」：选项是「全部修复（🔶🔷）」「只修重点（🔶）」「全不修复」。
- [ ] 只有 🔴 和 🔷 时留下的是「只修核心（🔴）」，没有「只修重点」：选项是「全部修复（🔴🔷）」「只修核心（🔴）」「全不修复」。
- [ ] 只有一级时，选项是「全部修复（那一级的图标）」「全不修复」。
- [ ] 每种情况下「全不修复」都在。
- [ ] 每种情况下推荐标记都在第一个选项上，位置在等级括号后面。
- [ ] 在「其他」里输入 `1,A`，编号 1 和「不建议修」表的 A 都交给 `/revise`。
- [ ] 选「全不修复」后没有调用 `/revise`，进入全量测试；选其余选项后选中的条目一次交给 `/revise`。
- [ ] `/git-push` 的说明里搜不到「修全部 🔴🔶」「只修 🔴」「建议项全修」「都不修」。

## 验证路径
1. 走 `/git-push` 到 ocr 审查，成立的条目三级都有 → 弹窗的问题和四个选项与约束一致，第一项带推荐标记。
2. 选「全部修复（🔴🔶🔷）」→ `/revise` 收到「建议修复」表的全部条目，没有「不建议修」表的条目。
3. 换一次只有 🔴 和 🔷 的审查 → 选项是「全部修复（🔴🔷）」「只修核心（🔴）」「全不修复」。
4. 选「全不修复」→ 直接进入全量测试。
