# README 改版

## 用户故事
### P1：作为第一次打开仓库的开发者，我想要 README 开头就讲清它是什么、为什么、怎么装，以便不用翻到底

**用例（主路径）**
- 场景：一位英文开发者打开 `README.en.md`。
- 操作：只看第一屏，再往下滚到安装。
- 预期：标语和徽章下方紧接着看到主页链接和「What it solves」三条差异点；往下只有一处安装说明；「阶段一览」每个命令只露出几行要点，想看细节可以展开。

**用例（边界）**
- 场景：维护者对照旧版 README 找某个外部链接或命令（如 `open-code-review` 链接、`claude plugin update` 命令）。→ 预期：在新版里都能找到，可能在折叠块里。
- 场景：读者点 README 顶部导航的任一链接。→ 预期：跳到对应章节。

## 约束
以下约束对五份 README（`README.md` 简体中文、`README.en.md`、`README.zh-TW.md`、`README.ja.md`、`README.ko.md`）同样适用，五份用各自语言写同样的内容、同样的章节顺序。

- **开头**：横幅、标题、标语、徽章、语言切换行保留；徽章行加一个指向 `https://bb-spec.0xbb.me/` 的主页徽章；徽章之后、第一个正文章节之前，有一个「它解决什么问题」章节（各语言用各自的标题），内容是三条差异点：三 Agent 隔离执行、磁盘文档作为唯一交接物、代码 ⇄ PRD 经 git 双向可查。
- **差异点只写一处**：「设计渊源」章节保留借鉴对比表，原来表后的「BB-Spec 自己的取舍」三条移到开头，「设计渊源」里不再重复这三条。
- **安装只写一处**：每份 README 里 `/plugin marketplace add 0xBB2B/bb-spec` 只出现一次；四个子插件的安装命令、`~/.claude/settings.json` 手动配置都在同一个安装章节里。快速开始引导读者去这个安装章节，日常 6 条命令表保留。
- **阶段一览折叠细节**：每个命令（`/git-clone`、`/prd`、`/plan`、`/exec`、`/doc-update`、`/git-push`、`/revise`、`/test-webview`、`/test-api`）在折叠块之外最多 3 条要点；其余原有要点放进这个命令下方的可展开折叠块（`<details>`），一条都不删。
- **Hook 只在一个章节**：「默认启用的 Hooks」表和「Hook 开关速查」表放在同一个章节里，相邻排列。「附带产物」里的被动 hook 列表那一行保留原文（现有测试按它校验）。
- **末尾章节**：「测试」和「从 13 及更早版本升级」移到 License 之前的末尾位置，不在用户正文中间。
- **导航有效**：顶部导航里每个链接都指向本文件中真实存在的章节；改动后不留指向已删除或已改名章节的链接。
- **不丢信息**：旧版每份 README 里出现过的每个外部链接地址和每条以 `/` 开头的 Claude Code 命令，在新版同一份 README 里仍然出现。
- **现有测试通过**：`tests/*.sh` 和 `tests/validate.sh` 全部通过（其中有检查 README 里 hook 表、被动 hook 列表、开关速查、子代理名单的用例）。

## 验收
- [ ] 五份 README 徽章行都有指向 `https://bb-spec.0xbb.me/` 的主页徽章。
- [ ] 五份 README 第一个正文章节是「它解决什么问题」（各语言标题），含三条差异点；「设计渊源」里没有这三条。
- [ ] 五份 README 中 `/plugin marketplace add 0xBB2B/bb-spec` 各只出现一次，安装命令和 settings.json 示例在同一章节。
- [ ] 阶段一览每个命令折叠块外最多 3 条要点，其余在 `<details>` 内。
- [ ] Hooks 表与开关速查表在同一章节且相邻。
- [ ] 「测试」「从 13 及更早版本升级」位于 License 之前的末尾。
- [ ] 五份 README 章节顺序一致。
- [ ] 顶部导航每个链接都能跳到本文件中存在的章节。
- [ ] 旧版每份 README 的外部链接集合和 `/` 开头命令集合，都是新版同一份的子集。
- [ ] `tests/*.sh`、`tests/validate.sh` 全部通过。

## 验证路径
1. 在 GitHub 上预览五份 README → 开头依次是标语、徽章（含主页徽章）、「它解决什么问题」。
2. 每份里搜 `/plugin marketplace add` → 只有一处。
3. 展开阶段一览任一命令的折叠块 → 看到原来的细节要点。
4. 逐个点顶部导航链接 → 都跳到对应章节。
5. 用脚本对比新旧版本的链接集合和命令集合 → 旧版的都在新版里。
6. 跑全部测试 → 通过。
