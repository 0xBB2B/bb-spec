# ocr 审查"修哪些"弹窗的选项

## 目标
`/git-push` 的 ocr 审查弹窗默认推荐全部修复，选项按范围从大到小排，括号里只写这次实际有的等级。

## 业务规则（来源：PRD 01-fix-options）
- 问题文字保持「ocr 核实后建议修 C 条（🔴 a · 🔶 b · 🔷 c），修哪些？」。
- 选项顺序：「全部修复」「只修重点」「只修核心」「全不修复」。
- 范围：「全部修复」是「建议修复」表的全部条目；「只修重点」是其中的 🔴 和 🔶；「只修核心」是其中的 🔴；「全不修复」一条都不修。四个选项都不含「不建议修」表的条目。
- 前三个选项名后带全角括号，按 🔴🔶🔷 的顺序写这次实际会修到的等级的图标，这次没有的等级不写；「全不修复」不带括号。
- 去掉选项的规则，按顺序判断：一条都修不到的去掉；「只修重点」和「只修核心」范围相同时去掉「只修重点」（原因：🔴 在选项里叫核心，留「只修重点（🔴）」名字和内容对不上）；其余和排在前面的选项范围相同的去掉。
- 「全不修复」始终保留；推荐标记在剩下的第一个选项上。
- 「其他」按输入的编号取，可含「不建议修」表的字母编号。
- 选「全不修复」不调用 `/revise`，进入全量测试；其余情况把选中条目一次交给 `/revise`。
- 说明里不出现旧选项名「修全部 🔴🔶」「只修 🔴」「建议项全修」「都不修」。

## 成品定义
`plugins/bb-spec-workflow/skills/git-push/SKILL.md`「### 用户勾选」小节里以「否则用 AskUserQuestion 问」开头的那一段，整段换成下面这一段（原样落盘，一个自然段，不换行）：

```markdown
否则用 AskUserQuestion 问「ocr 核实后建议修 C 条（🔴 a · 🔶 b · 🔷 c），修哪些？」，选项依次为：全部修复（Recommended）/ 只修重点 / 只修核心 / 全不修复。每个选项修的范围：「全部修复」是「建议修复」表里的全部条目，「只修重点」是其中的 🔴 和 🔶，「只修核心」是其中的 🔴，「全不修复」一条都不修；四个选项都不含「不建议修」表里的条目。前三个选项名后面带全角括号，括号里按 🔴🔶🔷 的顺序写这个选项这次实际会修到的等级的图标，这次没有出现的等级不写：三级都有时是「全部修复（🔴🔶🔷）」「只修重点（🔴🔶）」「只修核心（🔴）」，没有 🔷 时第一项是「全部修复（🔴🔶）」。去掉选项按下面的顺序判断：某个选项这次一条都修不到（如没有 🔴 时的「只修核心」），去掉它；「只修重点」和「只修核心」修的范围相同（只有 🔴 和 🔷 时），去掉「只修重点」；剩下的选项里，某个选项和排在它前面的选项修的范围相同（如没有 🔷 时的「只修重点」），去掉它。「全不修复」始终保留，Recommended 标在剩下的第一个选项上。用户选「其他」时按输入的编号取（如 `1,3,A`，可含「不建议修」表的字母编号）。
```

同一文件「### 修复」小节，段首的「选「都不修」→ 进 4.3。」换成：

```markdown
选「全不修复」→ 进 4.3。
```

这一段其余文字不动。
