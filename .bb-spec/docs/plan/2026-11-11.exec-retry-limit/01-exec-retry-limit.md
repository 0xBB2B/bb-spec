# /exec 实现重试和自修上限改成 2 次

## 目标
`/exec` 规程写明：实现重试每个 plan 最多 2 次，自修每个 plan 最多 2 轮；规则校验测试断言新写法。

## 业务规则（来源：PRD 01-two-attempts）
1. 实现子代理（Impl Agent）写完后测试有失败，`/exec` 把报错发回让它再改，每个 plan 最多 2 次；第 2 次之后仍有失败，停下报告用户。
2. 实现子代理报告「方案问题」时，不做实现重试。
3. 审查发现实现不符合 PRD、且原因确定是实现写错（impl-defect 且根因确凿）时，`/exec` 自修，每个 plan 最多 2 轮；第 2 轮后复查仍有不符合，标 blocked 并报告用户。
4. 每轮自修流程相同：补测试、改实现、重新审查。
5. 重新审查报出的问题，无论和上一轮是不是同一条，都算在同一个 plan 的 2 轮之内。
6. 同类位置和测试缺口跟着当轮自修一起做，不另算轮次。
7. 补出来的测试失败，按实现写错处理，占 1 轮自修。
8. 实现重试次数和自修轮数都按每个 plan 分别算。
9. 每轮自修无论成败，都记进 PROGRESS.md 并计入完成简报。
10. 插件目录和测试目录里没有「最多 1 次」「一次自修」这类按旧上限写的句子。

决策理由：用户遇到过"再试一次就过"却被打断的情况；2 次仍是有限上限，防止 `/exec` 反复改个不停。

## 成品定义
`plugins/bb-spec-workflow/skills/exec/SKILL.md` 里四处原文替换，其余文字一字不动。

**① 「2b. Impl Agent — Green」一段**

原文：
```
有失败 → 反馈错误给 Impl Agent 重试（最多 1 次）；
```
改成：
```
有失败 → 反馈错误给 Impl Agent 重试（每个 plan 最多 2 次）；
```

原文（同一段末尾）：
```
其余不重试，直接进下方「归因」；仍失败 → 仍失败报告用户。
```
改成：
```
其余不重试，直接进下方「归因」；第 2 次重试后仍失败 → 报告用户。
```

**② 「按根因分流」的 impl-defect 一条**

原文：
```
**自行闭环不打断用户**：补测试(Red) → 改实现(Green) → 重新 Review；自修**最多 1 次**仍不过 → 标 blocked 上报用户。无论自修成败都在 PROGRESS.md「当前」区如实记一笔并计入完成简报。
```
改成：
```
**自行闭环不打断用户**：自修**每个 plan 最多 2 轮**，每轮都是补测试(Red) → 改实现(Green) → 重新 Review；重新 Review 报出的 ❌ 无论和上一轮是不是同一条，都算在这 2 轮之内；第 2 轮后仍不过 → 标 blocked 上报用户。每轮自修无论成败都在 PROGRESS.md「当前」区如实记一笔并计入完成简报。
```

**③ 「测试缺口当轮补」一段**

原文：
```
失败说明实现有问题，按 impl-defect 在这一次自修里改实现。
```
改成：
```
失败说明实现有问题，按 impl-defect 改实现，占 1 轮自修。
```

**④ 「测试缺口当轮补」后面一段**

原文：
```
同类位置和测试缺口跟着上面 impl-defect 的那一次自修一起做，不另算次数；复查仍有 ❌ 的按上面的规则标 blocked。
```
改成：
```
同类位置和测试缺口跟着上面 impl-defect 的当轮自修一起做，不另算轮次；2 轮自修后复查仍有 ❌ 的按上面的规则标 blocked。
```
