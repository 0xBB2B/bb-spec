# 同根因位置一次修完

## 目标
`/revise` 留在本流程修问题时，动手前把同一个根因牵连的其他位置搜全、列表通报、和用户报的那一处同一轮修完。

## 业务规则（来源：PRD 01-same-cause-fix）
- 什么时候搜：`/revise` 诊断定出根因、决定留在 `/revise` 修时，动手前搜一次；结论是转 `/prd` 的不搜。
- 什么算同根因位置（满足任一条）：调用了出问题的那段代码或读了出问题的那份数据、会受同一缺陷影响；没有调用它但在别处独立写了同样的错误写法。同一个文件里的另一种缺陷不算。
- 搜哪里：出问题的代码所在的整个仓库；多仓库工作区里每个用到这段代码的代码仓库都搜。
- 每个位置读过代码再下结论，带 `文件:行号` 和理由；处理只有三种：一起修、不用修、另开需求。
- 诊断结果增加「同根因位置」一节（根因、搜了什么、五列表格、合计一行）；没有其他位置时只写一行"同根因位置：搜过了，没有其他位置（搜了：…）"。
- 通报后不等用户确认直接修。只有某个位置有多种合理修法、且用户看到的结果不同时，只就这一处停下问。
- 要新增设计或改变用户原本想要的行为才能修的位置标"另开需求"，本轮不改，其他照常修。
- "一起修"的位置属于本次修复必须改的范围，改它们不用另外请用户批准。
- 每个"一起修"的位置至少一条先失败后通过的测试，审查逐个位置核对，全部改动在同一次本地提交里。
- "跳过三个子代理直接修"的条件（1 个文件、10 行以内）按全部"一起修"的位置合计。
- 用户一次报多处：根因相同的合并、只搜一次；根因不同的各搜各的。
- 写实现的子代理发现表外的同根因位置时不自己改，在报告里写位置和理由；Claude 核实后补进表里、本轮修完。
- 完成简报增加一行"同根因位置：共 N 处，修了 A 处，不用修 B 处，另开需求 C 处"，只算表里的位置；另开需求的逐条列出。
- 用词统一为"同根因位置""用户报的那一处"，不出现"兄弟位点""主位点"。
- 决策理由：两次实际经过里用户每次都回答"一起修"，所以通报后直接修；同根因位置被划到范围外是反复修的直接原因，所以写明它在范围内。

8. **最小影响**：只改必须改的层，不借修正之名扩展功能或重构（额外需求走 `/prd`）；同根因位置（步骤 2「同根因搜索」表里处理为「一起修」的）属于必须改的范围，和用户报的那一处同一轮修完，改它们不用另外请用户批准

**③ 步骤 0**：以 `**多位点同类问题**` 开头的整段改成：

````

````

**④ 步骤 2**：在诊断决策树的代码块之后、`**向用户通报诊断结果**` 一段之前，插入：

````
**同根因搜索**（归因完成、去向是留在 `/revise` 时做；去向是转 `/prd` 的跳过）：动手修之前，把同一个根因牵连的其他位置一次搜全。

- **什么算同根因位置**（满足任一条）：① 调用了出问题的那段代码，或读了出问题的那份数据，会受同一个缺陷影响；② 没有调用它，但在别处独立写了同样的错误写法。同一个文件里的另一种缺陷不算
- **搜哪里**：出问题的代码所在的整个仓库（调用处用 codegraph 或 grep 函数名，同样写法用 grep 关键写法）；多仓库工作区里，每个用到这段代码的代码仓库都搜
- **逐个读代码判断**：搜到的每个位置都读过代码再下结论，带 `文件:行号` 和一句理由。处理只有三种：
  - **一起修**：受同一缺陷影响，和用户报的那一处同一轮修完
  - **不用修**：读代码确认不受影响（如调用前已自己做过检查），理由带那段代码的 `文件:行号`
  - **另开需求**：要新增设计、或要改变用户原本想要的行为才能修；本轮不改它，其他位置照常修
- **只为取舍停下**：某个位置有不止一种合理修法、且不同修法下用户看到的结果不一样时，用 AskUserQuestion 只问这一处，问完和其他位置同一轮修完。其余情况通报后直接进步骤 3

结果写进诊断结果的「同根因位置」一节；没有搜到其他位置时，这一节只写一行 `同根因位置：搜过了，没有其他位置（搜了：<函数名或关键词>）`。
````

**⑤ 诊断结果模板**：在代码块里 `- 去向：<留在 /revise / 转 /prd — 一句话原因>` 这一行之后追加（仍在同一个代码块内）：

````

## 同根因位置（去向是转 /prd 时不写这一节）
根因：<一句话>
搜了：<函数名或关键词>

| # | 位置 | 类别 | 处理 | 理由 |
|---|---|---|---|---|
| 1 | <文件:行号> | 调用处 / 同样写法 | 一起修 / 不用修 / 另开需求 | <一句话> |

共 N 处：一起修 A 处，不用修 B 处，另开需求 C 处。
````

> **同根因位置一起修**：步骤 2 表里处理为「一起修」的位置和用户报的那一处是同一个问题、同一轮修完。Test Agent 的输入列出全部位置，每个位置至少一个先失败的用例；Impl Agent 的函数清单覆盖全部位置；Review Agent 逐个位置给结论；全部改动进同一次本地 commit。Impl Agent 在报告「表外同根因位置」里上报了位置时，主 agent 读代码核实，成立的补进步骤 2 的表、在本轮修完。
````

改动 ≤ 1 个文件 ≤ 10 行（用户报的那一处和全部「一起修」位置合计）+ 修复逻辑显而易见
````
