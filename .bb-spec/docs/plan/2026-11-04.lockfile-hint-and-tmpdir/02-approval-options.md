# 批准弹窗选项

## 目标
所有批准新技术的弹窗，预设选项都是"同意""不同意"，用户也可以在"其他"里直接写意见。

## 业务规则（来源：PRD 2026-11-04.tech-approval-options / 01-approval-options）
- 问题仍是"上面 N 项新技术，你同意引入吗？"；预设选项依次是"同意"（说明"按这份清单引入"）和"不同意"（说明"Claude 接着问你要改哪几项、改成什么"）；"其他"直接写意见。不出现"全部同意，继续""否决其中几项"。
- 选"同意"：按清单引入。选"不同意"：Claude 在正文问"要改哪几项？改成什么？"，停下等回复，不再弹窗。
- 在"其他"里写意见或回复追问后：只替换提到的项，其余不变；说了具体技术的来源标"用户点名"；整份清单再列一遍、再弹一次窗，直到用户选"同意"。
- 用户不要任何新技术：改用标准库和项目已在用的技术完成；做不到就停下说明。
- 做计划、执行、修 bug、普通对话用同一套选项（exec、revise 都引用 version-policy 的格式，不各自写选项）。

## 成品定义
**version-policy §2「批准方式」**：从 `- 选项依次是"全部同意，继续"` 那一行起，到 `用户选"全部同意，继续"之前，不改依赖文件` 那一段结束（含这两行之间的全部内容）替换为：

```markdown
- 选项依次是"同意"（选项说明写"按这份清单引入"）、"不同意"（选项说明写"Claude 接着问你要改哪几项、改成什么"）；工具自带的"其他"用来直接写意见

按回答处理：

- **同意** → 按清单引入，版本按 §3 查最新
- **不同意** → 在回复正文问"要改哪几项？改成什么？"，停下等用户回复，不再弹窗
- **在"其他"里写了意见，或回复了追问** → 只替换用户提到的项，其余项内容不变；用户说了具体技术的，替换上的项来源标"用户点名"。然后把整份清单再列一遍、再弹一次窗，直到用户选"同意"
- **用户不要任何新技术** → 改用标准库和项目已在用的技术完成；做不到就停下，说明卡在哪一项需求，不自行引入

用户选"同意"之前，不改依赖文件和配置文件（如 `go.mod`、`package.json`、`Dockerfile`、`compose.yaml`、`.github/workflows/*`），不写引入新技术的代码。
```

**version-policy §8**：`- [ ] 用户已选"全部同意，继续"，或这些项已在经用户批准的「新增技术」表里` → `- [ ] 用户已选"同意"，或这些项已在经用户批准的「新增技术」表里`

**plan/SKILL.md 步骤 3**：A `选项依次是"全部同意，继续"、"否决其中几项"**。否决几项就只替换这几项，整份清单再列一遍、再弹窗，直到用户选"全部同意，继续"；在此之前不写 plan 文档。` → B `选项依次是"同意"、"不同意"**，按 version-policy 的「批准方式」处理：选"不同意"时在正文追问要改哪几项、改成什么；用户写了意见就只替换提到的项，整份清单再列一遍、再弹窗，直到用户选"同意"；在此之前不写 plan 文档。`

**plan/SKILL.md 步骤 6**：A `用户已选"全部同意，继续"（没有新技术则未询问）` → B `用户已选"同意"（没有新技术则未询问）`
