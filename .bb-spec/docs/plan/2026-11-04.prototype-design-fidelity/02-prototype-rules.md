# /prototype 规程：DESIGN.md 与取证顺序

## 目标
`/prototype` 出原型前先过 DESIGN.md；照什么画按 DESIGN.md → 源码 → 问用户要不要跑服务的顺序找依据；框里画改动所在的整个页面。

## 业务规则（来源：PRD 01-design-doc、02-prototype-fidelity）
- 每次出原型第一步先读 DESIGN.md（单仓库在项目根目录，多仓库工作区在文档仓库根目录）。新建、修改都要用户同意才写入；草稿只放对话或缓存目录。
- 没有 DESIGN.md、已有界面代码 → 读全局样式、布局组件和组件代码，起草 DESIGN.md 如实记录现状（含页面框架和组件写法），列出不达标处和修改建议，请用户确认；确认前不出原型。
- 没有 DESIGN.md、没有界面代码 → 按项目类型出 2～3 套达标风格放进同一份原型的 `schemes` 对比，选定后写成 DESIGN.md；选定前不出要设计的页面。
- 已有 DESIGN.md 但缺项或不达标 → 列出问题和建议，确认后先改 DESIGN.md。用户不接受某条建议 → 在「无障碍」一节记例外（项、实际值、确认日期），按现状继续，以后不再报。
- 用到规范外的颜色、字号、间距、圆角、阴影、组件样式 → 逐个标出问用户；同意写进 DESIGN.md，不同意改用规范里有的。
- 写法标准：10 节；不适用写"不适用"和原因；颜色按用途命名写色值，支持深色写两套；WCAG 2.2 AA（正文 4.5:1；大号文字即 24px 及以上或 18.66px 及以上加粗、图标、输入框和按钮边框 3:1）；间距圆角取 4 的倍数（全圆角写 9999px 算例外）；数值写单位、不用形容词；组件 6 种，各写写法和 5 种状态；「布局与断点」写页面框架的位置、尺寸、写法、断点变化；终端界面写颜色、符号、表格、进度条。
- 取证顺序：DESIGN.md 写了这次涉及的页面框架和组件的样子与写法 → 只按它画，不读源码；缺哪部分 → 只读那部分源码，整理成补充内容问用户，同意才写入；读完源码仍定不下来（运行时生成的结构、运行时计算的样式、画布内容）→ 列出定不下来的部分，问用户要不要跑；不同意 → 按源码画，`fake` 标出可能不准的部分。
- 跑服务只在用户同意后：先列出完整命令和出处（文件、行），依赖没装一并说明，用户再次同意才执行；抓渲染后的 HTML 和最终样式当底稿，去掉 `<script>`、内联事件属性、真实用户数据，只改要改的部分；抓完立即关服务；启动失败、2 分钟打不开、要登录、没有能打开网页的工具时也立即关掉，改按源码画，`fake` 写清卡在哪。
- 框里画整个页面（顶栏、侧边栏、导航、页面标题、周围组件）；组件和页面框架照 DESIGN.md 的写法，没写的照源码的 HTML 结构和类名；`note` 写依据：DESIGN.md 章节、源码文件路径、底稿地址。
- 终端原型按 DESIGN.md「终端界面」和输出代码还原，定不下来时同样问用户要不要运行；项目配色写进页面的 `terminalCss`；外壳默认终端配色只在项目没有命令行输出代码时使用。

## 成品定义

**1. frontmatter 的 `description`** 整行换成：

```
description: 界面原型的唯一规程——先读项目根目录的 DESIGN.md（没有就起草、不达标就先补齐，都经用户确认），按 DESIGN.md 画出改动所在的整个页面，缺的只读对应源码，源码定不下来才问用户要不要跑服务；用统一的蓝图外壳出 HTML 原型：左栏切页面和状态、右上角切方案和明暗主题、中间的框只放正式页面、底部放说明，多方案放同一份原型切换，改到用户明确说"可以"；也负责做完后拿实际界面和原型对比。触发：/prototype、做个原型、出个界面预览；/prd、/revise 要出原型时调用；/exec、/revise 收尾时用 --compare 调用。跳过：改动不影响用户看到的界面。
```

**2. 在 `## 出原型` 之前插入两节**（`## 模式` 那张表之后）：

```markdown
## 设计规范（DESIGN.md）

DESIGN.md 是项目的设计规范。出原型、写界面代码、审查界面代码都以它为准。它放在 `bbspec-paths.sh` 输出的 `docs_repo` 的根目录，`docs_repo` 为空时放在输出的 `root`：单仓库就是项目根目录，多仓库工作区是文档仓库根目录。新建和修改都要用户明确同意后才写入这个位置；草稿只贴在对话里，或写在 `${CACHE_DIR}/DESIGN.draft.md`。

**写法标准**（起草和检查都按这几条）：

- 必须有 10 节：风格定位、颜色、字体与字号、间距、「圆角、边框、阴影」、布局与断点、组件、动效、无障碍、终端界面；项目用不上的一节写"不适用"和一句原因。结构照 `${CLAUDE_PLUGIN_ROOT}/templates/DESIGN.md`
- 颜色按用途命名（如主色、背景色、次要文字色、错误色），每个颜色写具体色值；项目支持深色模式时明暗两套都写
- 颜色对比度符合 WCAG 2.2 AA：正文文字对背景至少 4.5:1；大号文字（24px 及以上，或 18.66px 及以上加粗）、图标、输入框和按钮的边框对相邻背景至少 3:1。对比度按 WCAG 的相对亮度公式算出来，不凭感觉判断
- 间距和圆角的每个值都是 4 的倍数（0 也算）；表示全圆角（胶囊形按钮、圆形头像）时写 9999px，不算违规
- 字号、行高、间距、圆角、阴影、动效时长都写具体数值和单位（px、ms 等），不写"简洁""大方""适中"这类形容词代替数值
- 「组件」一节至少写按钮、输入框、表格、卡片、弹窗、提示条，每种写写法（HTML 结构和类名）和默认、悬停、按下、禁用、聚焦 5 种状态的样子；项目里用不到的组件写"不适用"
- 「布局与断点」一节写页面框架：顶栏、侧边栏、导航的位置、尺寸和写法（HTML 结构和类名），以及不同断点下怎么变
- 「终端界面」一节写命令行输出用的颜色（按用途命名、写具体值）、符号、表格和进度条格式；不是命令行项目写"不适用"
- 已记在「无障碍」一节「例外」表里的项，检查时不再报

**出原型前先过一遍 DESIGN.md**：

1. 第一步先读 DESIGN.md，读完才开始设计
2. 没有 DESIGN.md、项目已有界面代码：读项目的全局样式、布局组件和组件代码，复制模板起草 DESIGN.md，如实记录现状，包括页面框架和组件的写法；同时列出不达标的地方和修改建议，请用户确认。确认前不出原型
3. 没有 DESIGN.md、项目还没有界面代码：按项目类型（如后台管理、面向大众的网站、命令行工具）设计 2～3 套达标的风格，作为 `schemes` 放在同一份原型里对比。每套风格的样式写在该方案 `html` 开头的 `<style>` 里，`css` 只写各方案共用的基础样式。用户选定后写成 DESIGN.md，删掉其余方案，把选中风格的样式移进 `css`，再出要设计的页面。选定前不出要设计的页面
4. 已有 DESIGN.md 但缺项或不达标：出原型前列出每个问题和修改建议，用户确认后先改 DESIGN.md，再出原型
5. 用户不接受某条修改建议：在 DESIGN.md「无障碍」一节的「例外」表记下哪一项、实际值、用户确认的日期，按现状继续
6. 原型里用到 DESIGN.md 没有的颜色、字号、间距、圆角、阴影或组件样式：在 `openQuestions` 里逐个标出，问用户。用户同意 → 写进 DESIGN.md 对应的一节；不同意 → 原型改用 DESIGN.md 里有的

## 取证顺序

照什么画，按下面的顺序找依据，前一步够用就不往下走：

1. **DESIGN.md**：这次涉及的页面框架和每个组件，DESIGN.md 都写了样子和写法 → 只按 DESIGN.md 画，不读源码
2. **源码**：DESIGN.md 缺这次涉及的某部分（页面框架、某个组件，或终端输出的格式）→ 只读这一部分对应的源码（如入口、路由、布局组件、导航、全局样式、组件库、改动所在页面里的相关代码）。读完把缺的样子和写法整理成 DESIGN.md 的补充内容，问用户，同意才写入
3. **问用户要不要跑**：读完源码仍定不下来样子（如组件库运行时才生成的结构、运行时计算的样式、画布绘制的内容）→ 列出哪些部分定不下来，问用户要不要把项目跑起来看。用户不同意 → 按源码尽量画，`fake` 里写明哪些部分可能不准

**跑服务**（只在用户同意后）：

- 先列出完整的启动命令和它的出处（哪个文件、哪一行），依赖没装时一并说明要装什么；用户再次同意才执行
- 跑起来后打开要改的页面，抓下渲染后的 HTML 和最终生效的样式当底稿；放进框里之前去掉其中的 `<script>`、内联事件属性（如 `onclick`）和真实用户数据（换成假数据）；只改这次要改的部分，不改的部分保持原样
- 抓完底稿，立即关掉为出原型启动的服务
- 启动失败、2 分钟内打不开要改的页面、页面要登录、或者没有能打开网页的工具时，也立即关掉服务，改按源码画，`fake` 里写清卡在哪一步

**画什么**：

- 框里画出改动所在的整个页面，包括顶栏、侧边栏、导航、页面标题和周围的组件，不只画改动的那一块
- 组件和页面框架照 DESIGN.md 的写法写；DESIGN.md 没写的，照项目源码里的 HTML 结构和类名写
- `note` 写明依据：用到了 DESIGN.md 的哪几节、读了哪些源码文件（写文件路径），用了底稿时写底稿来自哪个地址

**终端界面**：按 DESIGN.md「终端界面」和项目的输出代码还原颜色、符号、表格和进度条；定不下来时同样按上面第 3 步问用户要不要实际运行命令看输出。项目配色写进这一页的 `terminalCss`；外壳默认终端配色只在项目没有命令行输出代码时使用。
```

**3. `## 出原型` 的编号步骤整段换成**（编号列表之前的"界面包括两类……也要出原型。"保持不变）：

```markdown
1. 按「设计规范（DESIGN.md）」先过一遍 DESIGN.md，再按「取证顺序」找齐依据。全新项目对比风格方案时才会在这一步创建原型文件，其余情况这一步做完才进入下一步
2. 确定文件位置。调用方给了 `--file` 就用它，否则是 `${CACHE_DIR}/ui-preview/<YYYY-MM-DD>.<主题>.html`（主题 kebab-case）
3. 文件不存在时，把 `${CLAUDE_PLUGIN_ROOT}/templates/ui-preview-shell.html` 复制到这个位置。文件已存在时直接改它，用户确认过的内容留着
4. 只改文件里 `PROTOTYPE-START` 到 `PROTOTYPE-END` 之间的填写区，格式按那里的说明写，外壳一律不改。正式页面只放进框里，框里禁止放说明或切换控件；说明写进 `note`（这个画面的说明）、`fake`（只在原型里成立）、`openQuestions`（还没确认的问题）
5. 写页面样式：按 DESIGN.md 写 `css`（用了底稿时就用底稿里抓到的样式），照实还原；写了 `css` 后默认页面样式完全不生效
6. 图形界面：按「取证顺序」画出改动所在的整个页面，画出正常、空数据、加载中、出错这几种状态，有交互的地方做成可点击的，框里的跳转用 `data-go`。终端界面：页面设 `terminal: true`，项目配色写进 `terminalCss`，多步交互每一步写成一个状态，并设 `stateLabel: '步骤'`
7. 同一次设计有多个方案时，都放进同一份原型的 `schemes`，不拆成多个文件；用户选定方案后，把没选中的方案删掉，再请用户确认
8. 用 `open <文件路径>` 在浏览器里打开给用户看
9. 用户提了意见就先改原型，再请用户看，直到用户明确说"可以"
```

**4. 「确认后」里「单独运行」那一条**换成：

```markdown
- 单独运行：告诉用户文件路径，到此结束。不写 PRD，不改产品代码；DESIGN.md 只按「设计规范（DESIGN.md）」经用户同意后写入
```
