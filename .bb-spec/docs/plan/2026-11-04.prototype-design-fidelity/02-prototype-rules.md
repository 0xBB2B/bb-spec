# /prototype 规程：DESIGN.md 与整页还原

## 目标
`/prototype` 出原型前先过 DESIGN.md，再拿真实页面当底稿或读代码整页还原，终端原型照项目实际输出。

## 业务规则（来源：PRD 01-design-doc、02-prototype-fidelity）
- 每次出原型第一步先读项目根目录（多仓库工作区为文档仓库根目录）的 DESIGN.md。
- 没有 DESIGN.md、已有界面代码 → 先读全局样式、组件和页面代码（能跑起来也看真实页面），起草 DESIGN.md 如实记录现状，列出不达标处和修改建议，请用户确认；确认前不出原型。
- 没有 DESIGN.md、没有界面代码 → 按项目类型出 2～3 套达标风格放进同一份原型的 `schemes` 对比，选定后写成 DESIGN.md；选定前不出要设计的页面。
- 已有 DESIGN.md 但缺项或不达标 → 出原型前列出问题和修改建议，确认后先改 DESIGN.md。
- 用到规范外的颜色、字号、间距、圆角、阴影、组件样式 → 逐个标出问用户；同意写进 DESIGN.md，不同意改用规范里有的。DESIGN.md 新建、修改都要用户同意后才写入。
- 写法标准：10 节（风格定位、颜色、字体与字号、间距、圆角边框阴影、布局与断点、组件、动效、无障碍、终端界面），不适用写"不适用"和原因；颜色按用途命名写色值，支持深色写两套；WCAG 2.2 AA（正文 4.5:1；大号文字即 24px 及以上或 18.66px 及以上加粗、图标、输入框和按钮边框 3:1）；间距圆角取 4 的倍数（全圆角写 9999px 算例外）；数值写单位、不用形容词；组件 6 种 × 5 种状态；终端界面写颜色、符号、表格、进度条。
- 能跑起来 = 有现成启动命令、不用登录、不用另配环境变量数据库外部服务、2 分钟内打开要改的页面；依赖没装先问用户。能跑 → 抓真实 HTML 和最终样式当底稿，只改要改的部分，说明里写底稿地址和改动点，出完关服务。
- 跑不起来或失败（启动报错、2 分钟打不开、要登录）→ `fake` 写清卡在哪；读入口、路由、布局组件、导航、全局样式、组件库、改动页面代码；框里画整个页面（顶栏、侧边栏、导航、页面标题、周围组件）；组件照项目 HTML 结构和类名；`note` 列出依据的源码文件路径。
- 终端：能运行命令用真实输出当底稿，不能运行照输出代码和 DESIGN.md「终端界面」还原；项目配色写进页面的 `terminalCss`；外壳默认终端配色只在项目没有命令行输出代码时使用。

## 成品定义

**1. frontmatter 的 `description`** 整行换成：

```
description: 界面原型的唯一规程——先读项目根目录的 DESIGN.md（没有就起草、不达标就先补齐，都经用户确认），照项目真实界面整页还原（能跑起来就拿真实页面当底稿），用统一的蓝图外壳出 HTML 原型：左栏切页面和状态、右上角切方案和明暗主题、中间的框只放正式页面、底部放说明，多方案放同一份原型切换，改到用户明确说"可以"；也负责做完后拿实际界面和原型对比。触发：/prototype、做个原型、出个界面预览；/prd、/revise 要出原型时调用；/exec、/revise 收尾时用 --compare 调用。跳过：改动不影响用户看到的界面。
```

**2. 在 `## 出原型` 之前插入两节**（`## 模式` 那张表之后）：

```markdown
## 设计规范（DESIGN.md）

DESIGN.md 是项目的设计规范，放在项目根目录（多仓库工作区放在文档仓库根目录）。出原型、写界面代码、审查界面代码都以它为准。它的新建和修改都要用户明确同意后才写入文件。

**写法标准**（起草和检查都按这几条）：

- 必须有 10 节：风格定位、颜色、字体与字号、间距、圆角边框阴影、布局与断点、组件、动效、无障碍、终端界面；项目用不上的一节写"不适用"和一句原因。结构照 `${CLAUDE_PLUGIN_ROOT}/templates/DESIGN.md`
- 颜色按用途命名（如主色、背景色、次要文字色、错误色），每个颜色写具体色值；项目支持深色模式时明暗两套都写
- 颜色对比度符合 WCAG 2.2 AA：正文文字对背景至少 4.5:1；大号文字（24px 及以上，或 18.66px 及以上加粗）、图标、输入框和按钮的边框对相邻背景至少 3:1。对比度按 WCAG 的相对亮度公式算出来，不凭感觉判断
- 间距和圆角的每个值都是 4 的倍数（0 也算）；表示全圆角（胶囊形按钮、圆形头像）时写 9999px，不算违规
- 字号、行高、间距、圆角、阴影、动效时长都写具体数值和单位（px、ms 等），不写"简洁""大方""适中"这类形容词代替数值
- 「组件」一节至少写按钮、输入框、表格、卡片、弹窗、提示条，每种写默认、悬停、按下、禁用、聚焦 5 种状态；项目里用不到的组件写"不适用"
- 「终端界面」一节写命令行输出用的颜色（按用途命名、写具体值）、符号、表格和进度条格式；不是命令行项目写"不适用"

**出原型前先过一遍 DESIGN.md**：

1. 第一步先读项目根目录的 DESIGN.md，读完才开始设计
2. 没有 DESIGN.md、项目已有界面代码：先读项目的全局样式、组件和页面代码（能跑起来时也看真实页面，判定方法见下一节），复制模板起草 DESIGN.md，如实记录现状；同时列出不达标的地方和修改建议，请用户确认。确认前不出原型
3. 没有 DESIGN.md、项目还没有界面代码：按项目类型（如后台管理、面向大众的网站、命令行工具）设计 2～3 套达标的风格，作为 `schemes` 放在同一份原型里对比；用户选定后写成 DESIGN.md。选定前不出要设计的页面
4. 已有 DESIGN.md 但缺项或不达标：出原型前列出每个问题和修改建议，用户确认后先改 DESIGN.md，再出原型
5. 原型里用到 DESIGN.md 没有的颜色、字号、间距、圆角、阴影或组件样式：在 `openQuestions` 里逐个标出，问用户。用户同意 → 写进 DESIGN.md 对应的一节；不同意 → 原型改用 DESIGN.md 里有的

## 拿底稿

"底稿"是从项目真实页面抓下来的 HTML 和最终生效的样式。

**判定能不能跑起来**：项目有现成的启动命令（如 `package.json` 的脚本、`Makefile` 目标、README 写明的启动步骤），不用登录、不用另配环境变量、数据库或外部服务，2 分钟内能打开要改的页面，就算能跑起来。依赖没装时先问用户要不要装，用户同意才装。

**能跑起来**：

- 跑起来后打开要改的页面，抓下渲染后的 HTML 和最终生效的样式，放进框里当底稿；只改这次要改的部分，不改的部分保持原样
- `note` 写明底稿来自哪个地址，以及这次改了哪些地方
- 原型出完后，关掉为出原型跑起来的服务

**跑不起来**（判定为跑不起来，或跑的过程失败：启动报错、2 分钟内打不开、页面要登录）：

- `fake` 里写清卡在哪一步
- 读项目的入口、路由、布局组件、导航、全局样式、组件库和改动所在页面的代码
- 框里画出改动所在的整个页面，包括顶栏、侧边栏、导航、页面标题和周围的组件，不只画改动的那一块
- 组件照项目里现有组件的 HTML 结构和类名写
- `note` 列出照着哪些源码文件还原（写文件路径）

**终端界面**：命令行项目能直接运行要改的命令时，用真实输出当底稿；不能运行时，照项目的输出代码和 DESIGN.md「终端界面」一节还原颜色、符号、表格和进度条。项目配色写进这一页的 `terminalCss`；外壳默认终端配色只在项目没有命令行输出代码时使用。
```

**3. `## 出原型` 的第 4、5 步换成下面三步，原第 6、7、8 步顺延为第 7、8、9 步，内容不变**：

```markdown
4. 按「设计规范（DESIGN.md）」先过一遍 DESIGN.md，再按「拿底稿」拿到底稿或读完代码
5. 写页面样式：按 DESIGN.md 和项目现有样式写 `css`（有底稿时就用底稿里抓到的样式），照实还原；写了 `css` 后默认页面样式完全不生效
6. 图形界面：在底稿或整页还原的基础上改，画出正常、空数据、加载中、出错这几种状态，有交互的地方做成可点击的，框里的跳转用 `data-go`。终端界面：页面设 `terminal: true`，项目配色写进 `terminalCss`，多步交互每一步写成一个状态，并设 `stateLabel: '步骤'`
```

**4. 「确认后」里「单独运行」那一条**换成：

```markdown
- 单独运行：告诉用户文件路径，到此结束。不写 PRD，不改产品代码；DESIGN.md 只按「设计规范（DESIGN.md）」经用户同意后写入
```
